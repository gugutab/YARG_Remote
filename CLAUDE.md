## 1. What it is

Web visualizer (HTML + ES modules, **no build**) for songs in the Rock Band / YARG format:
- the user points to a songs folder (`A:\music\Songs\`, or any folder; or `node server.mjs` serves one), the app lists the songs;
- on picking a song, they choose instrument and difficulty, and the app plays the audio stems with a synchronized highway (notes, sustains, solos, star power, rolls, HOPO, open, drums, vocals with lyrics);
- controls: play/pause, seek, sections, per-stem volume, speed (0.2×–2×) without changing pitch, neck speed (spacing only), chart delay (−1 s to +1 s, per window), audio delay from `song.ini`, A-B loop.
- There is no hit/miss detection. It is visualization only.

**Language.** The user writes **Portuguese**; chat replies and discussion with the user are in Portuguese. Everything in the repository is **English**: code, comments, UI text, docs (this file, README) and commit messages.

**UI labels (English):** instruments Guitar, Bass, Rhythm, Keys, Drums, Vocals, Harmony; difficulties Easy, Medium, Hard, Expert (badges E/M/H/X from the `short` field of `DIFFICULTIES` in `chart.js`); drum modes "Drums (4 lanes)", "Drums (5 lanes)", "Drums (Pro)", "Drums (Pro 7 lanes)"; panels Library, Settings, Stem volume, Other song.ini properties.

**Not supported** (pending, in order of likely value):
- `.sng`: not the YARG-encrypted wrapper variant; a `.sng` inside a folder that is also a song is a separate song.
- `.chart`: no GHL tracks, no co-op guitar (`DoubleGuitar`), no versus phrases (`S 0`/`S 1`), no anchors or `[Song] Offset` (ignored, as in YARG), no kick accent/ghost (`N 33`/`N 39`, reserved in YARG), no vocal pitches (a `.chart` has lyrics only, drawn as talkie notes). Forced, tap, open, double kick, cymbal, accent and ghost flags are per difficulty (YARG.Core `ChartReader.ProcessLists.cs`), and so are star power, solo, fill and roll phrases and the tom markers: those notes carry `difficulty` and `buildChart` filters on it (`ChartReader.ReadNotes`, `ConvertSoloEvents`).
- Pro guitar and bass (`PART REAL_GUITAR`, `REAL_BASS`) and Pro keys (`PART REAL_KEYS_*`).
- Open by 5-lane note pattern (only the SysEx and `[ENHANCED_OPENS]` forms are read).
- Fill: band plus activation note marks (see the drum fills bullet at the end); BRE: its own pulsing band only, no scoring, no coda `Coda` phrase.
- Elite Drums (`PART ELITE_DRUMS`) and VENUE/lights.
- Solo only as a background band (star power also recolours its notes, `markStarPowerNotes` in `highway.js`). The comparison with YARG's render and suggestions are in `docs/yarg-render-review.md`. Do not extend solo to per-note without checking YARG first.
- Lyrics: `§`/`=` handled only in a basic way; `#`, `+`, `^`, `*`, `%`, `/`, `$` are hidden but their meaning is applied (§6). The Unity-side vocal UI is not in YARG.Core, so how YARG draws talkies and uses range shifts is inferred from the data.

## 3. Run, test, verify

```bash
npm start              # node server.mjs [songsDir]; env SONGS_DIR, PORT=8080, HOST=127.0.0.1, CACHE_DIR; open http://localhost:8080
npm run start:static   # python -m http.server 8080 --bind 127.0.0.1 (folder picker only, no server features; use python3 where `python` does not exist)
npm test               # node --test test/*.test.js, no browser: 520 tests at last run (the only place the count is written)
npm run smoke          # scripts/smoke.mjs: server on a free port + temp synthetic song; non-zero exit on any failure
node scripts/find-special-notes.mjs <folder> [--only open,accent] [--max 5] [--json]
```

- Dev server: `node server.mjs [folder]` (default `A:\music\Songs`, or `SONGS_DIR`). The app detects it (`startLibrary` in `app.js`) and opens the library with no folder picker. `HOST=0.0.0.0` is the explicit LAN opt-in (§8.12). The refresh button redoes the scan. Index cache: `.cache/library.json` (git-ignored).
- `smoke.mjs` backs up and restores `.cache/library.json` (the server overwrites it, and it holds one `songsDir` only).
- Unit tests use synthetic MIDIs from `test/smf.js` (an SMF writer for tests only). **Do not commit the user's real songs**: they are copyrighted and stay outside the repository (`.gitignore` blocks audio, `.mid`, `.sng`, `song.ini`).
- The `Read` tool does not read `.mid` (binary). Inspect with the project parser (`src/midi.js`) or a Python script with `struct`.

**Visual verification** (a unit test is not enough for drawing; take a screenshot):
- Playwright from `npm root -g`; system Chromium: `chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })` (Linux sandbox). Do not run `playwright install`. On Windows the Playwright MCP browser also works (`.playwright-mcp/` is git-ignored; screenshots at the repo root too).
- Load a folder with `page.setInputFiles('#folderInput', '<directory path>')`. The input is `webkitdirectory`, so it needs a real directory, not a file list. Or run `node server.mjs <folder>` and just open the page.
- Each test song is a folder with `notes.mid`, `song.ini` and a silent `song.wav` (audio is needed for the song to open; an 8 kHz mono WAV of N seconds works; `scripts/smoke.mjs` has a WAV writer).
- Position with `#seek` (`value` plus `input` and `change` events), or open a deep link (§8.1 Deep links).
- The canvas has height `min(70vh, 620px)`. Crop the screenshot to the full height or the lyrics (below the canvas) are left out.
- Do not use `pkill -f <pattern>`: the pattern matches the shell itself and kills the session (exit 144). Keep the PID of the server and `kill` it.
- Browsers block sound before a click, so a headless run cannot start playback by itself; headless only checks the clock.


**Perf recipe.** Settings `perf.overlay` (off/compact/detailed, key P or click the chip) shows fps, frame avg/p95/max, draw ms, dropped frames (gap > 1.5× median or > 25 ms), long tasks, canvas size, dpr, panes, JS heap (Chromium), audio output latency and "music clock jitter" (`perf.clock`). Notes-on-screen and audio drift are not measured. To find garbage per frame: Playwright `page.context().newCDPSession(page)`, `HeapProfiler.startSampling` with `includeObjectsCollectedBy*GC`, then sum `selfSize` per function after `stopSampling`. Measure frame time at the display's vsync (e.g. 6.4 ms at 160 Hz). Reference numbers are in §8.7.

Songs the author used for manual checks are listed in §9.

## 5. Data model and clock

Chart (`buildChart`):
- `mode`: `'lanes'` (guitar, bass, rhythm, keys, drums) or `'vocals'`.
- lanes: `notes[] = {time, end, length, lane, cymbal, tap, hopo, open, accent, ghost, doubleKick}`, `lanes`, `laneColors`, `drumKind`, `rolls[]`, `solos[]`, `starPower[]`, `fills[]`, `beats[]`, `sections[]`, `duration`. In drums, `lane = -1` is the kick (full-width bar, not a column).
- vocals: `notes[] = {time, end, length, pitch}` (plus `slide`, `talkie`), `harmonies[] = {part, notes}`, `percussion[] = {time, played}`, `lyrics[] = {time, text, end}`, `phrases` (karaoke lines), `rangeShifts`. Harmony: `chart.lyrics` are YARG's merged static lyrics (karaoke without split), `lyrics1` the lead voice's own words, `lyrics2` the other voices' own words (what the lead does not sing at the same moment).

Library index (`server.mjs`): each song `{id, folder, title, artist, album, ini, parts, files:[{name,path}]}`. `parts` = the instruments its chart really has (from `instrumentOptions`; harmony counts as vocals). `song.ini` often has no `diff_*` or -1 for all, so list icons and the instrument filter use `parts` when present and fall back to the ini levels (folder mode has no `parts`). `INDEX_VERSION` is 4 (4 = .sng songs). Bump it when the index gets new fields so `.cache/library.json` is rebuilt (a full scan reads every chart, ~8 s for 746 songs).

Pack (game/DLC): `packOf(song)` in `ini.js` = the top-level folder of the song's path (40 values in the author's library: "Rock Band 2 DLC", "Guitar Hero III"...; the ini `icon` code is partial). Shown as the first header chip, a line in the large card, a filter, a sort key with dividers, a `pack:` search field (and part of free-text search). Songs in the library root have no pack.

Clock: `player.currentTime()` = chart position. The highway receives `t − chartDelay`, so a positive delay makes the notes arrive after the audio. The current section, lyrics and karaoke use the same time as the highway: changing one without the others breaks alignment.

## 6. YARG rules

Source: `yarg.core` at `github.com/YARC-Official/YARG.Core`. Reference clone used: `/home/user/yarc-official/yarg.core` (may not exist in a new session; clone with `GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1 https://github.com/YARC-Official/yarg.core`). Cite the origin (file and function) in code comments for MIDI rules, as is already done.

| Topic | Rule | Where in YARG.Core |
|---|---|---|
| Difficulties | Base 60/72/84/96 (Easy/Medium/Hard/Expert). Offsets 0–4 = lanes; +5 and +6 = forced HOPO and forced strum. | `MidiInstrumentPreparser.cs`, `MidiFiveFretPreparser.cs` |
| Tap | Note 104 marks a window `[start, end)`; notes inside are tap (all difficulties). | `MidReader.ProcessLists.cs` |
| Natural HOPO | Not a chord, has a previous note (another fret or chord) and distance ≤ `resolution/3 + 1`. | `MoonNote.IsNaturalHopo`, `MidReader.cs` |
| Forced | A 101 window forces HOPO; 102 forces strum. Strum wins over HOPO. | `MidReader.cs` (`ProcessEventAsGuitarForcedTypePostDelay`) |
| Open | SysEx `PS\0`, type 0, difficulty (0–3, 0xFF = all), code 1 = open, value 1 start / 0 end, F7. Notes in the window become open. | `PhaseShiftSysEx.cs`, `MidReader.cs` |
| Enhanced opens | Text `[ENHANCED_OPENS]` / `ENHANCED_OPENS` in a 5-fret track: from that tick on, the note one below each difficulty's green (59/71/83/95) is an open note (`n.open`, lane 0). | `SwitchToGuitarEnhancedOpensProcessMap`, `BuildGuitarNoteProcessDict` (`FretToMidiKey[Open] = -1`) in `MidReader.ProcessLists.cs` |
| Sustain | A note has a sustain if it lasts ≥ `resolution/3` ticks. Drums have no sustain. | `SustainCutoffThreshold` in `MidReader.cs` |
| Drums: type | 101 present = 5 lanes; 110–112 present = Pro; otherwise 4 lanes. | `MidiDrumsPreparser.cs` |
| Drums: pads | Offsets 0 kick, 1 red, 2 yellow, 3 blue, 4 orange (5 lanes) or green (4 lanes), 5 green (5 lanes). | `DrumPadToMidiKey` in `MidReader.ProcessLists.cs` |
| Cymbal (Pro) | Yellow, blue and orange/green are **cymbal by default**. Notes 110/111/112 are **tom markers**: the window of each one does an XOR. Cymbal = even number of markers covering the note. The 5-lane mode applies cymbal flags too (the user asked for this explicitly; do not remove it without asking). | `DrumPadDefaultFlags`, `PAD_TO_CYMBAL_LOOKUP` in `MidIOHelper.cs`, `ProcessNoteOnEventAsFlagToggle` (`note.flags ^= flags`) |
| Pro 4-lane mode | Same notes, no cymbals. The option appears as "Drums (4 lanes)". In the selectors (cards and top menu) the drums are a single item, "Drums", with a mode selector (4 lanes / 5 lanes / Pro / Pro 7 lanes); `instrumentGroups()` in `app.js` (vocals and harmony are also a single "Vocals" item with a selector). | `MoonNoteToFourLane` |
| Pro 7 lanes | Mode id `drums-extended`: 7 lanes, tom and cymbal each in their own (`EXTENDED_DRUM_LANES` in `chart.js`); cymbals drawn as triangles. In YARG this is per profile (Split/Merge in `DrumsHighwaySpecs.cs`); the exact order after the split was not confirmed. | `DrumsHighwaySpecs.cs` |
| Accent / ghost | Velocity 127 = accent, 1 = ghost, pads only (not kick). | `MidIOHelper.VELOCITY_ACCENT/GHOST` |
| Double kick | A note one below the difficulty's kick (95 on Expert) becomes its own kick, at its tick, with the flag. | `MidReader.ProcessLists.cs` (`key - 1` with `InstrumentPlus`) |
| Rolls | 125 kick roll, 126 tremolo, 127 trill (time spans). | `MidIOHelper.cs` |
| Fills / BRE | Drums: notes 120–124 are activation phrases (`chart.fills`, kind `fill`); with a `coda`/`midcoda` event those starting inside a coda become `bre`. Guitar-like parts: note 120 is a BRE, valid only entirely inside a coda. Coda ranges: `midcoda`…`midcoda_end` pairs and a last `coda` to the end. | `DRUM_FILL_NOTE_*`, `ReplaceDrumFillDuringCoda`, `GetCodaRanges` (`MidReader.ProcessLists.cs`); `ValidateGuitarPhrase` (`MoonSongLoader.Guitar.cs`) |
| Sections | Text in the `EVENTS` track as `[section Name]` or `prc_name`. Current section = last one started; before the first, the first. The name is the text after the `section`/`prc` prefix with leading `_` and spaces trimmed; `displaySectionName` only tidies it for display (underscores to spaces, each word capitalised: `chorus_1` → Chorus 1, `gtr_solo_a` → Gtr Solo A; no abbreviations expanded). A song with no sections gets ten automatic ones, `0% - 10%` … `90% - 100%`, over the song's last tick (`autoSections` in `chart.js`). | `TextEvents.TryParseSectionEvent`, `PracticeManager.FindSectionAtTime`, `SongChart.AutoGeneration.cs` |
| Time signature / beat grid | Meta 0x58 (numerator, denominator = 2^n) → `midi.timeSignatures`. BEAT track notes 12/13 win; with none, lines every `resolution*4/denominator` ticks, restarting at each signature change, a measure line every `numerator` lines (x/1: only the first), default 4/4. | `SyncTrack.GenerateBeatlines` (`FinishLoading`) in `Chart/Sync/SyncTrack.cs`; `ReadSongBeats` in `MidReader.cs` |
| Tempo | Tempo map summed across all tracks (meta 0x51), integrated `tick → seconds`. | `SyncTrack.cs` |
| Delay | `delay` (ms) if ≠ 0, otherwise `delay_seconds`. File position = chart time + delay. | `SongMetadata.cs`, `SongRunner.cs` |
| Wait countdowns | A chart with nothing to play for 9 s or more (also before the first note) shows a ring with the seconds until its next note, per pane; suppressed in a coda. | `GetWaitCountdowns`, `WaitCountdown.MIN_SECONDS` |
| Lyrics | Lyric events (meta 0x05) in the vocal track; if there are none, text without brackets (e.g. `5395826e`, `5875318f`). | `MidReader.cs`, `LyricSymbols.cs` |
| Lyric symbols | Hidden: `+ # ^ * % / $`. `=` = hyphen. `§` = joined syllables (`‿`). `-` stays. | `LyricSymbols.cs` |
| Vocals | Notes 36–84 (0 range shift, 1 lyric shift; 96 played and 97 not played are percussion). Harmonies: `HARM1`–`HARM3` or `PART HARM1`–`HARM3`. | `MidIOHelper.cs` |
| Vocal phrases | Notes 105/106 are scoring and static lyric phrases (`phraseRanges` in `vocals.js`). Lyrics go to the notes in a phrase by tick; a lyric takes the length of its nearest unclaimed note and lyrics no note claims are dropped (`chart.lyrics[].end`). HARM3 uses HARM2's phrases. | `MoonSongLoader.Vocals.cs` (`GetVocalsPhrases`, `FixLyricLengths`), `MidReader.ProcessLists.cs` (`CopyDownPhrases`) |
| Karaoke lines | `chart.phrases` = static lyric phrases split at lyric-shift notes (note 1; else the end of a syllable marked `/`), at gaps ≥ 0.4 s between syllables (not after a joined one), and by character count (> 50: `ceil(chars/37.5)` chunks, cut at the first word boundary past the target). | Pitch slide / talkie | A lyric ending in `+` makes its note a continuation of the previous one (`slide`, drawn joined; no syllable of its own); `#`, `^`, `*` make the note unpitched (`talkie`, drawn as a dashed box in the middle of the range, ignored by the range). | `LyricSymbols.cs`, `MoonSongLoader.Vocals.cs` (`GetVocalsPhrases`, `GetVocalNotePitch`) |
| Range shifts | Points: note 0 (length = its duration), `[range_shift]` / `[range_shift 0.5]` text, lyric ending in `%`. With more than one range `Highway.vocalRange` uses the one in force at `t` (eased over its length); with one, it scans ahead. | `GetRangeShifts` |

## 8. Gotchas by area

### 8.1 Library window and details pane
- **The window.** `#library` is ONE glass window floating over the stage (inside `#stage`, `position:absolute`, `--lib-gap` 12 px margin, `z-index` 12, `--panel` 78%), a flex row of two panes: `#libList` (`.lib-list`, with `#splitter`) and `#info` (song details; `hidden` and `inert` while closed; `#infoWindow`, `#infoWinTitle`, `#infoWinArtist`, `#infoClose`, `#infoPlay`; role dialog, aria-modal false). Border, shadow and blur are one layer, `.library::before`: never put `backdrop-filter`/`filter` on the aside or on `#info`. The window never takes room from the chart (the stage always spans the screen); it sits between the top edge and the player bar (bar at the bottom or the top). The chart and the bar stay live behind it.
- **Open/close.** `setLibraryOpen` toggles `.app.lib-closed`, `setInfoOpen` toggles `.app.info-open`; `syncWindow()` then sets `.details-only` (details open, list closed: only the details pane, anchored at `--lib-left`; closing them hides the window; L / `#libTab` bring the list next to it) and `inert` on the aside (no pane shown) and `#libList`. Slide/fade is transform + opacity (0.22 s); hidden is `visibility:hidden`, so the virtual list keeps its size. Library: L, `#libTab`, `#closeLibrary`, `#welcomeOpen`; details: I, Esc, `#infoClose`, Play; `#infoBtn` closes the details while open (capture-phase handler), else opens its popup. `#settingsTab` (gear edge tab, shown while the list is closed) and `,` reach Settings. Only one of library window and Settings is open at a time: opening Settings closes the list then the details (not remembered); opening the library closes Settings (`onOpen` of `mountSettings`). `setInfoOpen` closes Settings on open, focuses the window and restores the opener's focus on close.
- **Width (`layoutWindow()` in `app.js`, on top of the shared frame: `libFrame.fit()` gives the window's width, `libFrame.setWidth()` publishes `--win-w` on `.app`)**: runs on open/close of either pane, resize, splitter drag and a `details.maxWidth` change; computes `--list-w`, `--info-w`, `--win-w` (list + details + 2 px border) from the content area (`--content-max`, centred, starting at `--lib-left` = `max(--lib-gap, (100% - --content-max) / 2)`). `CONTENT_MAX` 1400 and `WIN_MARGIN` 12 (`src/windowframe.js`) and `INFO_MIN_W` 380 (`app.js`) must match the CSS defaults (`--content-max`, `--lib-gap`, the `.info` width fallback; `test/css-js-constants.test.js`). The content area is 1400 px and grows up to 3840 px (4K) when `details.maxWidth` asks for more (`contentMax()` = `max(1400, list + details max + margins)`, also set on `:root`). The list keeps its chosen width (`--lib-w`, remembered in `yargremote.libWidth`; min `MIN_LIB_W` = 300); the details get `min(details.maxWidth, room - list)`; when both do not fit the list shrinks first (`maxLibWidth()` leaves the details `INFO_MIN_W` while open), then the details go narrower than 380. `#splitter` is the list pane's right edge (window edge while details are closed, divider while open); double-click resets. Closing the details next to the list grows the list by the freed room only up to `LIST_GROW_MAX` (640 px, or its own preferred width if larger); the grown width is NOT remembered (`libWidth` changes only by dragging). A `/play` link closes the details without growing (`setInfoOpen(false, { grow: false })`). Width animates (`transition: width`, off while dragging).
- **Insets.** `.app` gets `--lib-inset` (`--lib-left` + `--win-w` + gap) while the list is open or `.details-only`; `.welcome`, `.end-screen`, `.load-screen` use it as `padding-left`. The canvas does not (the leftmost fretboard and the perf overlay sit under the window).
- **Outside click.** In details-only mode a pointerdown outside the whole `#library` closes the details (ignored: `.sel-pop, .popover, #infoBtn, #libTab, #scrim, #topbar`); with the list open next to them the window stays (the chart behind it is usable).
- **Edge dock.** `#edgeDock` is a handle on the left edge (`#dockHandle`, a chevron tab) that is shown only while the library window is closed and the details are not open (`syncPanelUi`, `body.details-open`). Hovering it (mouse) or clicking/tapping the handle grows the dock itself (26x76 -> 58x112 px, the arrow fades out) and shows `.dock-buttons` inside it: the Library button `#libTab` and the Settings button `#settingsTab` (44 px, no outer panel of their own); it folds when the pointer leaves (350 ms), on Esc, on a tap elsewhere, or when focus goes to another element (a blur with no target is ignored: the app blurs clicked buttons). A mouse click on the handle keeps it open (hover already opened it); a touch toggles, using the state at pointerdown because focusing the button opens it before the click arrives. The old `.edge-tab` rules are gone; `#libTab` keeps the 1 s hover peek (`setupPeek`).
- **Phone (≤ 700 px).** The window is a full-height fixed drawer with `#scrim` over the bar (CSS sizes it; `layoutWindow` removes its variables). Starts open only if the URL names no song. With details open it shows only `#info` at full width, edge tabs hidden, X returns to the list, Play closes the drawer; picking a song does not close it. `#settingsTab` is hidden (Settings via `#libTab`, then the gear in the library header).
- **Starting playback** (details Play, or the first Play of a song) closes the library window (both panes, not remembered, in `togglePlay`). A `/play` link at startup opens with the library closed whatever `panels.libraryStart` says; a details link (`#/song/<id>`) keeps the usual start state. Picking another song while details are open slides the new ones in (`selectSong` toggles `.info-swap` for 450 ms; fade + 18 px slide, `backwards` fill, motion on only).
- **Details content.** About one column of cards at least 380 px wide; the header shows the title (18 px, up to two lines, `text-wrap: balance`) and artist (14 px); in one column (`@container (max-width: 651px)` on `.info-grid`) the cover spans the window and the title/artist beside it are hidden (kept if there is no cover). The album art fills its card edge to edge (`.info-head` has no padding; `.info-head-text` carries it; in one column it is `display: block`); corners facing the text use `--radius`. Footer: only the Play button, edge to edge with square corners (the window clips its bottom corners); `#infoProgress` shows only in the error state (the load screen shows progress). Card list padding 8 px left/top, 12 px bottom (5/5/6 compact); 18 px kept on the right for the scroll thumb. Cards are translucent `--panel` without their own blur.
- **Panels settings.** `panels.libraryStart` (open/closed/last; state in `yargremote.panelState` `{library}`) and `panels.libraryAutoHide` (desktop only: close the list when a song is picked, default false; details stay). Removed: `panels.songStart`, `panels.openSongOnSelect`, the `songPanel` shortcut (D), `#songTab`, `#closeSongInfo`, the `song-closed` state.
- **Peeking** (`setupPeek`, `PEEK` timings): resting the pointer on the tab of a hidden menu for 1 s opens it temporarily (nothing saved); it closes 2 s after the pointer leaves or 3 s after it stops moving over it, unless a popover is open or an input inside has focus. A click opens it for good. None on touch screens or phones.
- **Large screens** (`styles.css`, "Round 56"): breakpoints at 1800, 2300, 3000 px widen the library (`--lib-w`) and the bar's content cap; the detail screen (`.info-grid`) is capped at 1400 px; the 2D lanes grow with the stage height (`laneW` in `highway.js`). CSS `zoom` was tried and rejected (breaks coordinates for popovers, the scrollbar rail and the canvas).
- **Deep links** (`src/route.js` and `src/deeplink.js`): the hash names the open song (`#/song/<id>` details, `#/song/<id>/play` chart); it is only replaced, never pushed, so Back leaves the app. A reload or shared link opens the same song (`openFromHash`). `/play` (startup, reload, hashchange) loads the audio with the song (`loadAudioWithSong` → `ensureAudio()`), ready to press Play (browsers block sound before a click); `#/song/<id>` loads no audio. Links carry instruments: `#/song/<id>/play?i=guitar:expert,bass:expert,drums-pro:expert,vocals` (active first, then pinned). `syncUrl()` runs at the end of `updateChart`; `applyInstruments` restores them (`pendingInstruments`). `parseRoute` keeps only easy|medium|hard|expert.

The top bar has no fullscreen button (F still toggles it); the settings button holds only speed (`#i-speed`). Removed: hamburger buttons, the bar's "hide song panel" button, `#partBtn` (instrument/difficulty/type live in the pane tag menus and details cards).

- **Glass.** The bar is full width, not a floating window: `.topbar::before` (`--panel` 78% + blur; bar itself transparent; compact bar background 52%), equal 12 px (10 px phones) padding above and below the expanded content. The visualizer and stage colour are drawn on one background canvas (`#bgCanvas`, first child of `.main`, `Highway.setBackgroundCanvas` / `drawBackground`) behind bar and stage; the fretboard canvas is transparent; the stage colour is the CSS background of `.main` (`setBackground`). The section selector (`.chip-btn`) has no background; icon-button hover is a 30% translucent panel; play keeps its accent.
- **Containers.** `.main { container-type: inline-size; container-name: song }`; narrow rules are `@container song (max-width: 700px)` (album art from 440 px), so they apply with the library open on a 700–900 px window. Others: `.info-grid`, `.card-volume`. Many bar rules depend on the *main area* width. Content width (> 700 px): `--bar-content-max` 1400 px centred, open and compact.

Main area ≥ 800 px: symmetric grid (cover | title | transport | tools | spacer) so the transport is centred on the bar; transport is two rows (`.tp-row1`/`.tp-row2`, `display: contents` elsewhere: prev/play/next, then time + section, 10 px under); prev/next 38 px, play 46 px; artist 15 px; two-line title balanced and shrink-wrapped by `fitTitleWidth()` (song change, resize) which sets `--info-offset` to centre the 24 px info icon on the longest line; third line `Pack - Charter` (`#tertiary`, `packOf(song)` + `song.ini.charter`) from 800 px.

### 8.3 Glass, blur, scrollbars and z-order
- **Containing-block trap:** never put `backdrop-filter`/`filter`/`transform` on an element that contains `position: fixed` popovers (it becomes their containing block; this once pushed the section list far right and made the page scroll sideways). Blur goes on `::before` (`.topbar`, `.library`, `.end-card`, `.settings-page`); `.popover`, `.sel-pop`, `.pane-menu` blur themselves (panel 78% + blur 16: no fixed descendants). Animations on glass use `backwards` fill only (`both` keeps a backdrop root alive and kills the blur).
- `<symbol>` + `<use>`: the document `svg path.fill` rule does not reach symbol contents, so `#i-play`/`#i-pause`/`#i-restart` carry inline `style="fill:currentColor;stroke:none"`.
- **z-order** (`z-index` in `styles.css`): `.stage-btn` 3, `.pane-tags` 3, `.perf-overlay` 4, `.stage-play` 5 < `.end-screen` 6 < `.load-screen` 11 < `.library` 12 (list and details together) < player bar 13 (and `.bar-ghost`; above the library so the bar's popovers are not hidden) < immersive bar 14 < `.popover` 20 < phone drawer `.library` 30 (`.scrim` 25 under it) < `.edge-tab` 40 < `.sel-pop` 50 < `.inst-tip` 60 < `.settings-page` 80 < `.seek-tip` 200. Keep a new layer in this order and update this line.
- **Scrollbars.** Every custom scrollbar (library rail, `.sthumb`, styled native ones) takes colours from the theme: `color-mix(in srgb, var(--accent) N%, transparent)` for thumb (16%), border (28%), hover/drag (30%); never a fixed blue. `src/scrollthumb.js` (`attachScrollThumb`; `thumbGeometry`/`scrollTopFor` tested in `test/scrollthumb.test.js`) is the overlay thumb in the library rail's style (7 px, flush right, native scrollbar hidden through `.thumb-scroll`, press the track to jump, drag the thumb; the scroller's parent must be `position: relative`): used by `.info-scroll` and `#settingsPage .sp-content`. Popovers, dropdown lists, the pane menu and the filter panel use native-scrollbar styling (7 px accent thumb).
- **Settings window:** `#settingsPage` is the second window of the shared window frame (see the "Shared window frame" bullet at the end of §8): same size rules, edges, glass, dim and motion as the library, minimum width `SETTINGS_MIN_W` 560 px, its nav turns into a row of tabs when the window is narrower than 760 px (`@container settings`), drawer at ≤ 700 px. Open/closed is the `win-closed` class + `inert` (no `hidden`). A pointerdown outside closes it (`.sel-pop`, `.popover` and the two opener buttons do not count as outside).

### 8.4 Stage hold and load screen
- **Held stage.** Picking a song while another is on screen (`holdStageNow` at the start of `selectSong`) freezes the fretboards (`holdStage` makes the frame loop's `draw` a no-op), hides `#paneTags` and the real bar (`.app.stage-held`) and lays a still clone of the bar over it (`.bar-ghost`, ids stripped, `inert`; it follows the real bar through a `ResizeObserver`, `ghostObserver`/`dropGhost`, no fixed pixel geometry). When the audio starts loading, `stageLoading()` removes the ghost and adds `.app.stage-loading` (hides `#highway` and `.bg-canvas`) so the load screen sits on the plain background. `releaseStage()` (does not touch `stage-unborn`/`stageEverLive`) runs when the audio has loaded (after `setLoadState('ready')`), when the details close with no load in progress, or on a load error; it lifts the hold and cross-fades bar, canvas and tags in (`.stage-reveal`, `stage-in` 0.35 s, motion on only). With nothing on screen nothing is held. A `/play` link also loads on the plain background (details close with `release: false`; `markStageLive()` and the load completion or error release it).
- **Load screen.** `.load-screen` has no background of its own: the stage shows through. While held audio loads, `draw` only repaints the background canvas (`highway.drawBackground`, driven by `loadingBackdrop`) so the chosen visualizer animates behind it. Audio loads on demand (`ensureAudio`, from Play, the Listen card or Space) behind `#loadScreen`; picking a song only reads the chart (a build failure shows 'Could not build the chart: ...'). `togglePlay` starts `ensureAudio()` before closing the details, so that close does not release the stage early. `ensureAudio`'s `finally` re-renders the load state so Play re-enables after a failure; a stale decode result after `player.load` calls `player.unload()` only when `loaded` is true. Selecting a song resets the bar (time, seek, section ticks, `activeSection`) to 0:00 until its audio loads. `playNext` has an in-flight guard. The seek bars `#seek` and `#npSeek` are exempt from the typing guard in the global keydown (Space and arrows work after clicking them); other sliders keep native arrows.

### 8.5 End window
- `ended` (with `endDismissed`, `setEnded`, `restartSong` in `app.js`; `syncEndScreen` and `isEndShown()` in `src/end-ui.js`) is set by `frame()` when playback runs out and cleared by `player.onSeek` (any `seek`/`scrubTo`), `restartSong`, `selectSong` and the `npPlay` handler. While ended and paused `#play`, `#npPlay`, `#infoPlay` show `#i-restart` and Space restarts (loop start or 0). `#endScreen` (`.end-screen`, in `#stage`, z-index 6, hidden while the details are open) is a glass window with a card per pane from `current.screen` (`{chart, key, icon, name, base, optionId, diffId, diffLabel, active}`, set in `updateChart`; stats from `songstats.js`), the "Play next" list, "Play again" and "View my library". `.app.song-ended` hides `#highway` and `#paneTags` with `visibility` (the visualizer keeps running; `highway.invalidate()` on show/hide). Padding-left `--lib-inset`; fade-in only with `data-motion="on"`. Esc only dismisses it. `general.endScreen` (default true) turns it off (the restart button stays).
- "Play next" rows show icons of the instruments the song has (`INSTRUMENTS` filtered by `hasInstrument`); the reason is the row tooltip. A recommendation opens through `selectSong` with `pendingInstruments`; `applyInstruments` falls back to the same kind by `base`. `.end-list` rows can shrink (`minmax(0, 1fr)`, `li {min-width:0}`, long titles ellipsise). `recommend` shows each title + artist once, never a twin of the current song (weights `WEIGHTS` in `recommend.js`, §4). `factRows(facts, {base})` hides HOPOs for keys.
- "View my library" (`#endSearch`, `closeSong()`) closes the song: audio unloaded, `current`/`chart`/panes cleared, bar gone (`stage-unborn`, `stageEverLive = false`), welcome state back, URL `#/`, library open with its search focused (in a `setTimeout`: the global click handler blurs buttons). "Back to search" focuses the search the same way. The instrument cards are flex items (`flex: 1 1 230px`, `max-width: 380px`, left aligned, wrapping): they grow from 230 to 380 px to fill the row.

### 8.6 Highway panes, vocals, karaoke, rests
- **Panes.** `Highway.setCharts([{chart,label}])` draws every chart (`drawPane` clips/translates, restores in `finally`, skips panes under 1 px; `setCharts` drops offscreen layers of gone panes). Vocals take a band across the top, lane charts sit side by side; when `width / paneMin` does not fit them all, `focus` selects the first in view (swipe/drag, keys `[` `]`, dots). `current.pins` holds pinned instrument groups next to the active one; the active chart drives timeline, sections and seek. `fitWidths()` (`panesizes.js`) lays them out so none is under `MIN_PANE_PX` (140) whatever the stored weights; sizes from localStorage go through `sanitizeSizes`.
- **Dividers.** Drawn by `Highway.drawDivider`, listed in `highway.dividers`; pointer handlers in `app.js` (`dragDivider`: weights per pane key, or `vocalH`), double click resets (`resetSizes`), sizes in `localStorage['yargremote.paneSizes']`. Dark (`rgba(0,0,0,0.25)`); hover/drag highlight uses the theme `--accent` (`themeAccent()`, re-read every 500 ms).
- **Tags and menu.** `Highway.paneRects` (per chart, every frame) places a DOM tag (`.pane-tag`, `syncPaneTags`, 34 px high, 22 px icons, see-through 0.3/0.55) in each window's top-right, also with one instrument; name + difficulty is tooltip/aria-label. It opens `#paneMenu` (`buildPaneMenu`): difficulty and type, swap/add another instrument (`replacePane`, `addPane`), view options (vocal view, 2D/3D, note shape), neck speed, chart delay, volume, then swap, add, remove (`closePane`, red; with one instrument = swap). Per-window options (neck, delay, 2D/3D, shape) apply only to that window (`Highway.paneOpts`, `setPaneOpt/paneOpt/clearPaneOpt`, applied around each pane in `drawPane`; reset on song open); `highway.neck` is the default, V/N and the global view/shape prefs set every window again. Neck speed also works on vocals: `VOCAL_PX_PER_SEC` (340 px/s) × `neck / global neck`.
- **Chooser and volume.** Swap/Add makes a pane without a chart (`chooser: true`) that `app.js` fills with instrument/type/difficulty cards (`fillChooser`, `current.choosers`); swapping the only instrument keeps it as timeline source (`current.hiddenActive`) until a card is picked; the slot's X cancels; "Add all" (2+ off screen) pins every one (`addAllInto`). `menuVolume(group)` (`src/tiles-ui.js`) reuses `mixerRow`/`groupBlock` for stems whose `stemGroup` is the instrument group key, as extra views of the same states (dropped by `dropMenuMixViews`); no section if the song has no such stem. Icon ids are used by `INSTRUMENT_ICON`/`CARD_INSTRUMENTS` in `app.js` and `stemKind` in `songinfo.js`.
- **3D.** Button ⬡ / V; note style (`noteShape` in `gfx.js`) button / N; both in localStorage. Overlays (star power, solos, fills, rolls) run to the end of the board (`ROAD_NEAR`). Road width (`renderLanes3D`): `0.94 * w` in a pane taller than wide, else `min(1.05 * h, 0.94 * h + 0.16 * (w - h))`: continuous at w = h and capped at 1.05 h, so past the cap widening only grows the side gaps.
- **Rests.** `Highway.restFade(pane, t, appearIn)` (0..1, eased) follows the pane's wait countdowns (`waitCountdowns`, independent of the countdown setting): it goes to 0 in a long rest and is back to 1 `REST_BACK_SEC` (1 s) before the next note appears at the far edge (`appearIn` = seconds a note is visible ahead of the hit line). The vocal view hides its lyric track with it; the whole fretboard (dark base, tint, bands, beat lines, lane guides, rails; `globalAlpha` around the board part of `renderLanes`/`renderLanes3D`) fades by `restBoard()` = `REST_BOARD_MIN` (0.2)..1 (fading the base alone looked whiter).
- **Vocal view.** Lyric row (bottom, and the harmony line above the chart) keeps a 0.72 base only with a visualizer; centred on the words (`lyricY = h - 0.75 × font`, middle baseline), font 24–36 px, 0.3 opacity, flush with the window bottom, fades out (0.2 s) with `chart.trackFade` (percussion section or countdown rest; needs countdowns). Note area base 0.15. Syllables have a dark outline (`strokeText`, 0.16 × font, min 3 px). The harmony line sits at the top edge; talkie boxes keep 10 px at the top; without a harmony line the pitch area starts 8 px from the top. `vocalCenterY` (percussion markers, countdown badge) uses the same pitch area as `renderVocals`. Band height default: alone `min(34%, 280) - 20`, with others `- 40` (90 px floor and dragged height unchanged). One note colour (`VOCAL_LEAD`), lighter past the hit line; percussion hits are drum-head markers on their own row. Countdowns (`Highway.drawCountdown`): left of the hit line in notes view, own row above the next line in karaoke; setting `highway.countdown`. Geometry in §6.
- **Karaoke** (`karaoke.js` + `Highway.renderKaraoke`): lyrics only, lines are `chart.phrases`, sung part filled per syllable; key K, "Vocals" group in the menu, `highway.vocalView`. Alone with harmony: two sheets (VOCAL 1/2, side by side when wide), each with its own scroll state (`Highway.sheets`, `sheetAt`, `scrollSheet`, `sheetLineAt`). Manual scroll (wheel/drag) holds the sheet (the active line keeps changing; the sheet scrolls only to keep it in view); the Autoscroll button shows only while out of view; autoscroll resumes with it, a seek or "jump to". Countdown rows precede every line after a rest ≥ 9 s (running = live ring, others grey with the length). A non-interactive rail at the right edge shows the song (`Highway.drawSheetRail`, `lyricCtx`). Karaoke has no base layer: lyrics sit on the stage/visualizer; lyric-sheet rows use their own layer (`rowLayer`) so edge fades erase only the words.
- Star power = background band + the phrase's notes in white with the lane outline (`markStarPowerNotes`); solo is a band only (§2). Pro drums show many cymbal rings (YARG's behaviour). `sectionIndexAt` returns the first section before any start: never use `-1` for "no section" when sections exist.
- `.chart` lyric phrases follow `TextEvents.ConvertToPhrases` (`buildEvents` in `chartfile.js`): a `phrase_start` inside an open phrase closes it there and opens the next, an unterminated phrase runs to the last event + 1, lyrics outside every phrase are dropped (no note either). Many charts write only `phrase_start` (Guns N' Roses "Coma": 135 starts, 23 ends); the old reader kept start..end pairs only and showed 187 of 1042 lyrics (now 1042). Test in `test/chartfile.test.js`.

### 8.7 Rendering layers, visualizers, perf
- **Board base and fades.** Fretboards have no stage-colour base: the road is a faint white tint with lane guides, over a neutral black base of opacity `highway.trackOpacity` (0–100, default 75), added last with `destination-over` so fades do not thin it. With a visualizer each lane pane is drawn on its own offscreen layer (`drawPane`/`layerFor`, `layer:<key>`, `this.layered`) and fades erase it (`destination-out`, `fadeStyle`): notes/guides/halos are erased, the base re-added. The top fade is a transparency mask over everything (3D 26% of height, 2D 12%, 12-stop smootherstep); the bottom fade only erases notes/guides (reads as fade to black) and is limited by the room under the pads (they must not move up: 3D keeps 26 px under them, 2D `HIT_Y` 0.93). Readability helpers never use the stage colour (vocal/lyric `trackBase`, karaoke dimming, sheet fades use black); `gfx.js` precomputes `EDGE_FADE_STOPS`, `BOTTOM_FADE_STOPS`, `LYRIC_RAMP_STOPS` assuming black fades.
- **Visualizers** (`visualizers.js`, `Highway.setVisualizer`, popover `#visualizerPop`, G / Shift+G): one animated background for the canvas, drawn in `Highway.draw` right after the background fill, under every pane (motion blur draws it once per frame). Every effect is a pure function of song time `t` (beat position from `chart.beats`, note density, star power spans, vocal/percussion activity, chart notes as a spectrum) plus the cover palette (32×32 downscale, `extractPalette`), so pausing freezes it and seeks just land; `createDriver` builds per-song data (`buildSongData`, rebuilt when `highway.panes` changes). Effects: Album art, Aurora, Synthwave, Warp, Beat rings, MIDI equalizer, Embers, Radial spectrum, Spotlights, Tunnel (default `none`). A throwing effect disables itself; `stats` keeps the running draw cost per effect. No audio analysis. They do not punch on the beat (`beat.pulse`/`measurePulse` forced to 0); no overlay/visibility slider; the stage colour reaches effects as `s.stage` ('r, g, b') / `hw.bgRgb`. Tests: `test/visualizers.test.js`.
- **Visualizer menu.** Effect list (`.viz-list`) and a foot (`.viz-foot`): blur slider (`highway.visualizerBlur`, 0–40 px, default 0, hidden with None) and a "Background" colour picker ("Theme" resets) setting `highway.stageColor` + `stageColorOn`, applied by `applyStage()` over the theme colour. Blur is a CSS glass layer, not canvas: `#bgGlass` (`backdrop-filter: blur(var(--viz-blur))`, shown through `.app.viz-glass` by `applyVizGlass`) between the background canvas and the chart, GPU-composited, notes stay sharp (the old canvas blur `drawBlurred`/`driver.blur` is gone; measured 1600×900 radial: 102 fps without, 99 with 24 px). Quality (`highway.visualizerQuality` high/medium/low = 1/0.6/0.4, default medium): the background canvas is drawn at that fraction and stretched (`Highway.vizScale`), since Radial/Tunnel/Warp are fill-rate bound; Album art is always full resolution. At 160 Hz vsync (6.4 ms): Radial 9.0 / Tunnel 8.7 / Warp 7.2 at high, 6.8 / 7.3 / 6.3 at medium, ~6.4 at low; JS cost at 1500×900 ≈ 0.15–0.2 ms.
- **Effect details.** Album art is cloth (48 vertical strips, `clothAt`, plain rgba slope shading, 1 px overlap, sharp 512 px copy, no beat flash, drift from song time only, camera pans over the whole cover with periods ~5 and ~6.5 min, `room` in `coverViz`; a two-pass version was rejected). MIDI equalizer hangs from the top (90% of height), each note lights a wide hill (`spectrumAt` `spread`), echoes 0.09/0.2/0.34 s back, glowing tip, falling peak caps. Radial spectrum (`radialLayout`: mirrored 2×40 bars around a ring, echo outlines, peak caps, the cover as a record turning with `beat.pos`, palette disc without a cover). Spotlights (`beamAngle`: 5–6 additive cones from the top, floor pools, haze; density/vocal brighten, star power warms). Tunnel (14 rounded 4-8-gons, see the tunnel bullet, at depth `fract(pos*0.05 + travel*0.12 + i/N)`, colours cycling the palette, twist eased per section with `sectionValue`). Aurora and Spotlights cap their own resolution at 0.5 (`maxScale`).
- **Idle skip.** `frame()` skips `highway.render` when the music is paused, no seek animation or drag, perf overlay off, nothing happened for 3 s (input, setting change, `highway.dirtyAt`), same time/canvas size/dpr/panes/chart as the last draw, and that draw is under 1000 ms old (`IDLE_REFRESH_MS`, `src/idle.js`: the decision is the pure `canSkipDraw`, tested in `test/idle.test.js`; `window.__yargDraws` counts the stage draws). With a visualizer an idle frame still calls `highway.drawBackground(t)` and skips the panes. Every Highway setter calls `Highway.invalidate()`: a new setter or any new non-input source of visual change must too (the 1 s refresh covers only hover tooltip delay and lyric easing). `delay`, `trackOpacity`, `sheetPeek`, `countdowns` are accessors that invalidate; so do `dragDivider`, `resetSizes`, `setSizes`, `scrollSheet`, `resumeSheet`. `perfMode` is cached by the `perf.overlay` EFFECT and the meters run only while the overlay is on; `#timeNow`/`#npTime` are written only when the text changes (`setText`). Tests: `test/idle-audio.test.js`.
- **Deep idle loop.** When `canSkipDraw`-style idleness holds and nothing animates by itself (`idleDeep` in `app.js`: paused, no seek animation/drag, perf overlay off, no visualizer, no loading backdrop, no start/resume/loop wait, 3 s without input or `highway.dirtyAt`), `frame()` schedules the next frame with a 1 s timer (`frameSleep`, `IDLE_REFRESH_MS`) instead of `requestAnimationFrame`. `wakeLoop()` restarts it at once from `wakeUp` (any input), `highway.invalidate()` (wrapped right after the Highway is created) and `syncPlayButton()`; anything else that changes the picture without those waits at most 1 s. The wait states (`startDone`, `resumeTimer`, `loopWait`) also keep `canSkipDraw` from skipping (the refresh is too slow for a countdown). Paused idle stage draws, Blaze of Glory guitar, 3 s windows: 12 per 3 s before (250 ms refresh) -> 3 per 3 s; playing is unchanged (162 draws/s on a 160 Hz screen). The pause panel writes only changed text (`setText(els.ppVolVal, ...)`: it was rewritten every frame, ~520 layouts and 1040 style recalcs per 4 s). Highway Star paused idle with the panel up, CDP over 4 s: 519 layouts / 1038 recalcs / TaskDuration 1.08 s before, 0 / 0 / 0.035 s after.
- **Lane scroll speed is fixed in pixels** (like the vocal view): `laneLookFactor(h)` in `gfx.js` (`h / LANE_REF_H`, reference 700 px, clamped 0.5-2.5) scales the visible time: 2D `pxPerSec = hitY / (BASE_LOOKAHEAD_SEC * factor) * neck`, 3D `windowSec = DEPTH_SEC / neck * factor`. A taller window shows more lookahead instead of stretching the same time; width never changed the speed. Note: a missing import in `highway3d.js` fails silently (the frame loop swallows draw errors and shows a toast), so check both views in a browser after touching the renderers.
- **Garbage.** Per-frame garbage was ~280 KB with 3 fretboards; now note outlines use one reused `Float64Array` (`gfx.js`), colour strings are cached per colour and quantised amount (`tintWhite`/`darken`/`withAlpha`), halo gradients (`fillHalo`, `fillTailHalo`) are cached per colour/size (Map capped at 96) with `globalAlpha` for strength, fill/roll span lists are cached per chart (`spansOfKind`), `renderLanes3D` indexes notes and `taperedStrip` reuses a scratch buffer, vocal notes draw through `vocalShape`, `mixstretch.js` reuses a scratch buffer, `scrub.js` has the scalar `grainSrcAt`/`grainWeightAt`. CDP heap sampler on Highway Star: ~7–8 → ~3.3–3.8 MB/s playing, ~5.5–6 → ~0.3 MB/s paused; frame time unchanged (p50 6.3 ms). Second pass (lane renderers): projection/time mapping live in module variables (`PK`..`PT` in `highway3d.js`; `LY_*`, `VOC_*`, `laneY`, `vocX`, `vocY` in `highway.js`) instead of per-call closures, so the renderers are not reentrant; the pad-flash array is a reused `Float64Array`, `draw` uses scratch arrays and pooled `paneRects`, `gfx.js` has `fadeGradient` and `boardBase`, caches for `starPowerColor`, halo stops, lyric font/`trackBase` styles and lyric widths, `vRange` eases in place, `syncPaneTags` compares numbers instead of building strings. Rule: in big render functions write the maths inline with the scale in a local (calls there boxed every number) and never quantise tint/alpha strings (that changes pixels). Reference (Highway Star, 3 panes, 1600x900, playing): 3D 3.1 -> 1.0 MB/s (20 -> 6.2 KB/frame), 2D 2.8 -> 0.9 MB/s; frame time unchanged (vsync, p50 6.3 ms). Proof it changed no pixel: 896 canvas hashes identical (2D/3D, round/rect, neck 1/1.5, guitar/bass/drums/keys/vocals/harmony, solos, star power, sustains, HOPOs, opens, fills, rolls). Still open (small): allocation inside `renderLanes3D`/`renderLanes` themselves (~0.4/0.25 MB/s), `fillHalo` rebuilding its gradient while a note is held, per-frame divider/sheet arrays, `fitWidths`, `frame`. Backdrop-filter on the stacked glass layers measured headless: ~+0.2 ms/frame of compositor draw, no frame-time change. The perf overlay repaints at most 4×/s; `frame()` times `highway.render`/`renderBlur`.
- **3D perspective and curve** (`highway.perspective` 60-160 %, default 120; `highway.curve` 0-100 %, default 25; Highway -> View, global, `Highway.perspective`/`curve` as fractions). `projection3D(h, hitY, strength, curve)` in `highway3d.js` (tested in `test/projection3d.test.js`) gives `PK`, `PVY`, `PC`, `PEND`: far scale = `FAR_SCALE / strength` (clamped 0.12-0.6), so the hit line and the flat far edge (`FAR_TOP`) never move; the curve adds `PC * d^2` px (down) for d > 0, where `PC` at 100 % cancels `CURVE_MAX` (0.9) of the flat slope at d = 1, and the road is cut at the crest (`PEND`, bisection) so it never folds back. Every y written in `highway3d.js` adds `(d > 0 ? PC * d * d : 0)` (inline, like the rest); with `PC > 0` quads become `curvedQuad` polylines (`CURVE_STEPS` 24 per depth unit) and rails/dividers `roadLine`; heads keep the flat taper (`vy` moves with the note) so the `drawYNote` cache keys are unchanged and heads are not squashed by the slope; the far fade moves down by `PC`. Curve 0 takes the old code paths: perspective 100 + curve 0 gave byte-identical canvas screenshots to the previous commit (Paranoid 18.6/30/60 s).
- **Cached note gradients.** `drawCymbalFace` (`gfx.js`, `cymbalGradients`: chrome plain/gold and the cone) and the 3D disc edge (`discEdgeGradient` in `highway3d.js`, plain/star power) build their gradients once in unit space and fill under a scale. The path must be added AFTER the scale, in unit coordinates (`fillCircleScaled`; the `unitY` proxy context that `noteShape` draws into): filling a path added before the transform changed rasterizes its edges differently in Chromium (up to 42/255 on edge pixels). Screenshots before/after (2D/3D, DPR 1/2, Highway Star at 18.7 s and 60 s): at most 26 pixels differ, by 1/255.
- **Flat note sprites.** A rectangular note is ~13 gradient fills and ~10 polygons. In 2D, `drawYNote(..., cacheable)` (caller passes `white === 0`: no held/exit tint) draws a note from a cached picture (`ynSprite`, gfx.js) when the context has a plain scale + translate, alpha 1, no filter, source-over: rendered once per colour, flags, size, side, DPR and device-pixel fraction (1/8 px, `YN_SPRITE_Q`), copied at a whole-pixel offset (no resampling); cap 800 (`YN_SPRITE_MAX`), cleared by `rebuildYNote`. 3D (taper and size change per row) and disabled, ghost-alpha or exiting notes draw directly. Highway Star drums Pro + guitar + bass, 1300x760 headless, render + GPU flush per frame: 2D rect 21.9 -> 15.5 ms (circles 14.4); 3D rect 23.4 (circles 17.9) unchanged. Pixels vs the direct path over 4 paused frames: 3.3% of pixels differ, 0.09% by more than 8/255, max 33 (1/8 px placement; compositing the fills into a transparent sprite alone gives max 9).
- **3D note sprites.** In 3D a steady rectangular note (not held, not exiting: `cacheable` = `kx === 0 && amt === 0` in `renderLanes3D`) has the same taper per design unit and the same aspect at every depth, so `drawYNote` draws it from `ynSprite3D` (gfx.js): one picture per colour/flags/size bucket (device half width rounded to a power of `YN3_STEP` 1.05, so the detail level is in the key too), rendered at `YN3_SS` (2) times the bucket size and drawn scaled to the exact size and sub-pixel place with `drawImage` (bilinear). Same canvas-state conditions as `ynSprite` (alpha 1, so far fade-in, ghost and disabled notes draw directly); cleared past 1200 sprites or 8 M px, or by `rebuildYNote`. Highway Star drums Pro + guitar + bass, 1300x760, real GPU (headless Chromium on ANGLE D3D11): uncapped rAF frame avg 8.4-9.5 -> 5.3-6.1 ms; render + getImageData flush 18.1 -> 15.1 ms (p95 22.3 -> 18.6); circles and 2D unchanged and pixel-identical. Pixels vs the direct path (6 paused frames: 60 s, 61.4 s, 95 s, 3:30, 5:56 BRE, one with tap/ghost/accent/star power/disabled flags forced): 0.7-2.3% of pixels differ, 0.04-0.1% by more than 16/255, max 46-63, all on note edges (resampling; supersampling 3-4x, 'high' smoothing or finer buckets did not lower it). Tried and dropped: sprites only for small notes (same max error, half the gain: the big near notes cost fill rate). Not done: cymbal discs (`drawCymbalFace`, removing them all saves only ~1 ms), CPU-side batching (the JS part of a 3D frame is ~1.4 ms; the cost is GPU).
- **Flow tail sampling.** A 3D flow tail (`drawFlowTails`, highway3d.js) is sampled once per frame (`sampleFlowTail`: centre x, y, unit half width, wave sine, into the `SMP_*` Float64Arrays) and the halo, body, core and spine strips (`flowStrip(g, k, widthMul, waveMul)`) only scale that width, so the perspective maths and the `sin` run once per point instead of four times. A swelling (held) tail has ~5 points per wave, capped at 30 and at one per 3 px of tail on screen (`waveSegments`: only bites below 90 px); the adaptive quality (any level above 0) lowers it to 3 per wave (`adaptiveEffects().wavePoints` -> `highway.tailWavePoints`; economy has no waves at all, `heldMotion` is off). The right-side scratch (`FLOW_RIGHT`) holds 31 points: the old 21-point one silently dropped the right edge of tails with more than 20 segments. Paused pixel signatures of the stage at 17 times of Blaze of Glory (guitar, Expert) differ by at most 1 part in 40,000 from the old code; main thread per frame with 4x CPU throttle, playing, 160 Hz: 3.17 -> 2.92 ms (3 runs each).
- **Resilience.** `frame()` schedules the next `requestAnimationFrame` first and runs each part (clock/loop, draw, pane tags, seek bar and time, perf) under `guarded(...)`: a throwing part cannot freeze the chart or seek bar. Errors go to `console.error` plus a toast through `createErrorGate` (at once, then the same message at most every 5 s). `Highway.render`/`renderBlur` call `recover()` on a throw (restores `this.g`, `layered`, `vizFrame`, canvas state). Tests: `test/resilience.test.js`.

### 8.8 Seek, scrub and A-B loop
- **Seek bar.** The thumb is hidden until hover, but `.seekbox.animating` (from `vis.anim` in `frame()`) keeps it during a seek animation. Thumb and time show the real position (already at the target); the fill and fretboards animate to it together (eased `shownTime`). While dragging, only thumb and time follow the pointer; the fill keeps following playback (`paintSeek(t)`) until release. Hovering shows `#seekTip` (section name and time; a handle's time over a handle), fixed-positioned so it works compact. Wheel over `#seekbox`: up = forward, 5 s per notch (1 s with Shift), clamped, only once the audio is loaded. Any other `input[type=range]`: one notch = one step (2% for fine-grained), touchpad fractions accumulate, `input` + `change` fire; bound per input, lazily on the first `pointerover`/`focusin` (`reachRange`: two passive capturing document listeners; `onRangeWheel` itself stays on the input, since a document-level non-passive wheel listener would make every list scroll wait for the main thread). Generic sliders (`GENERIC_RANGE`) are painted (`--p`) by wrapped `value`/`min`/`max` setters, a capturing `input` listener, once at start and on `reachRange`; there is no document MutationObserver any more, so a new generic slider must get its value through `.value` after it is built.
- **Seek bar writes.** `paintSeek` (`--pct`) and `setSeekValue` (thumb) run every frame but write only on change; while playing they round down to whole device pixels of the bar (`seekBarPx`, from a ResizeObserver with `devicePixelContentBoxSize`), paused they write the exact position. `.animating` is toggled only when it changes. Highway Star playing 5 s: ~420 layouts / ~500 style recalcs before, 23 / 28 after.
- **Seek animation** (`visualChartTime`): eases only the time the highway draws on a jump > 0.75 s between frames (seek bar, wheel, arrows, section, lyric line): ease-out, 0.28 s + 25 ms per second of distance, 0.7 s max. Clock, sections and audio use the real time. `highway.seekAnimation`. **Motion blur** (`highway.motionBlur`): while the drawn time moves faster than 0.06 s/frame, `Highway.renderBlur` draws 8 moments across that frame's step (offscreen canvas, running 1/(i+1) alpha average).
- **Adaptive motion blur.** Each blur sample is a whole chart draw: on Highway Star with drums Pro + guitar + bass (1300x760, headless) 8 samples made the 0.7 s seek animation run at ~18 fps (13 frames, gaps up to 85 ms), so the jump looked stuck. `blurSampleCount` (app.js) / `adaptBlurSamples` (gfx.js) halve the samples after a blurred frame slower than 25 ms and add one after a frame under 18 ms (2..8), and keep the count for the next jump: 37 frames, max gap 38 ms (blur off: 67 frames). Test in `test/highway.test.js`.
- **Scrub on seek.** While playing, a long seek (> 0.75 s, animation on) goes through `seekTo` → `player.scrubTo(t, ms)`: the worklet (`player-worklet.js`, `scrub.js`) rushes through the skipped stretch as short Hann grains following the same ease-out path for the same duration (`seekAnimMs`, handed over by `pendingSeekDur`), then plays from the target with a short fade-in. The chart clock is the target at once. Paused seeks, the loop wrap and the legacy engine cut the audio immediately.
- **A-B loop** (`looprange.js`, pure, `test/loop.test.js`; UI in the Loop block of `app.js`, `#loopBtn` / key R). A range of **player time** (seek bar scale): survives instrument/difficulty changes, cleared when a song opens. Starts around the current section (t ± 10 s without sections); handles (`#loopStart`/`#loopEnd`, pointer capture) snap to section starts and song ends within 10 px (Alt disables), minimum 1 s; `#loopBand` highlights it. The frame loop wraps only when playback leaves the end from inside (`shouldWrap`), asking `player.outputLatency` early; the audio restarts at once (`player.seek`, no scrub) and only the fretboards animate the rewind (`pendingSeekDur = 450` ms, motion blur included, animation setting on). Section list rows have a loop button (no loop: loop that section; outside: extend; inside: narrow). When a section button or handle drag leaves the playhead outside the loop, `rewindIntoLoop` seeks to its start.
- **Loop wrap in heard time.** The wrap is asked `outputLatency` early (so the new start is heard right after B), but the chart clock used to jump at that moment: the fretboards left the loop one output latency before B and swept back (450 ms animation) over notes that lit up as the hit line passed them, while the old audio was still playing. Now `wrapLoop` seeks with `player.seek(back, { heard: true })`: `jumpHistory` (clock.js) keeps the old clock history for audio times before the restart, so `currentTime()` runs on to B and jumps when the new start is heard; `player.jumpPending` is true until then (the replay window, the "song ended" check and `pendingSeekDur` wait for it; a pause in between resumes from the new start). A backward seek animation lights nothing it sweeps over: `highway.litLag` = drawn − real time, `setLitLag`/`litFrom` in gfx.js gate the pad flashes and `heldAmount` (2D and 3D). Tests in `test/loop.test.js`.
- **Speed trainer** (`trainer.js`, pure, `test/trainer.test.js`; settings `practice.trainer*` in General → Practice, off by default; On/Off + status line `.trainer-box` appended to `#settingsPop` by `app.js`). A pass = one completed wrap, counted at the top of `wrapLoop()` (the only restart path: the frame wrap, `finishLoopWait` after the restart delay, the `loopHeld` Play), so the delay counts once; the speed is set through `setSetting('speed')` before the wrap's seek, so a step starts with the new pass. After `trainerPasses` passes the speed rises by `trainerStep` (snapped to the slider's 0.05 grid, clamped to the target; a target at or below the start is done at once). A new loop (`setLoop` from no loop) or turning the setting on during a loop sets the start speed; ending the loop (R, a seek outside it, another song) or turning it off keeps the speed reached; moving a handle keeps the progress. A speed moved by hand is where the ramp goes on from. `#settingsBtn.trainer-on` tints the speed button while it runs; flash notes "Speed trainer: Speed 60%" and "Speed 70%" / "(target reached)". It never touches the wait/rewind state machines.

### 8.9 Settings, themes, shortcuts

### 8.10 Audio and player
- `player.js` uses an `AudioWorklet` (`player-worklet.js` + `mixstretch.js`) that mixes all stems and time-stretches (SoundTouch) once, with a single read position. The chart clock interpolates the position history the worklet reports (`clock.js`) at `ctx.currentTime − output latency` (extrapolating with the speed caused jumps on speed changes; reports arrive ahead of what is heard; `epoch` discards reports prior to a seek). This fixed the stem/chart desync of the old engine (one `ScriptProcessor` per stem, kept as the `LegacyPlayer` fallback, whose latency the highway clock does not compensate). Test: `test/mixstretch.test.js`.
- **Smooth clock.** `WorkletPlayer.currentTime()` runs on the real clock between frames and is pulled to the audio position (time constant 0.15 s; gaps over 0.1 s snap), since the raw clock moves in steps (reports every ~12 ms). Jitter rms 4.6 ms / max 10 ms before, 0.5 / 1.2 ms after; with the frame's own timestamp (`player.frameNow`) rms 0.3 ms. The perf overlay's "music clock jitter" checks it.
- **Start watchdog.** `AudioWorklet.addModule` can stay pending forever in Chrome ("Loading audio" stuck at 2%, empty console). `WorkletPlayer.setup()` gives up after `WORKLET_START_MS` (6 s) and `MultiTrackPlayer.load` falls back to `LegacyPlayer` (warning "AudioWorklet unavailable, using the legacy player"). Cause unknown; gone in a fresh browser context.
- **Unload.** `player.unload()` frees the decoded stems (worklet `unload` message / legacy buffers), invalidates in-flight loads (generation bump in `LegacyPlayer` and `WorkletPlayer`; `WorkletPlayer.load` takes its generation before the setup await) and resets the position to 0; called when another song is picked and at the start of every `load()`, so the peak is one song, not two. Test: `test/player-unload.test.js`.
- **Decode memory.** A decoded stem is float32 (a 6:09 stereo stem ~130 MB). `alignOrKeep` (`player.js`) hands the decoded channel itself to the worklet (transferred) when the delay rounds to 0 samples, and copies (`alignChannel`) only when it shifts; `LegacyPlayer.alignBuffer` returns the decoded buffer then. A stereo stem whose channels are identical (`sameChannels`) keeps one channel (the mixer plays `ch[1] || ch[0]`, bit-identical). Decodes take an estimated size (`estimateDecodedBytes`: WAV x2, compressed x24) from a shared 640 MB budget (`createBudget`/`withBudget` in `stemdecode.js`, `DECODE_BUDGET_BYTES`) on top of `DECODE_PARALLEL` = 6, so long songs decode a few at a time. Highway Star (7 stems, dedicated headless Chromium, private bytes): peak 2.3-3.5 GB before, 1.4-2.1 GB after; settled ~1.40 -> ~1.28 GB; time to ready unchanged (~5 s). Tests: `test/delay.test.js`, `test/resilience.test.js`.
- **Idle suspend.** The AudioContext suspends after 30 s paused (`AudioIdle`, `suspendDue`, `SUSPEND_AFTER_MS` in `clock.js`); `play()` awaits `ensureRunning()` with a 1.5 s timeout (`RESUME_TIMEOUT_MS`, `settlesWithin`) and stays paused if the browser will not resume.
- **Stem decode failures.** `decodeAll` (`stemdecode.js`) decodes stems one by one and skips throwers (`console.warn` with the id); only if none decodes does `load()` fail (first error's message). `setVolume` of a failed id is a no-op; `player.failedStems = [{ id, label, error }]`; `app.js` marks those `stemStates` `failed` (row disabled, tooltip "Could not be decoded"; ready text "N stems could not be decoded"). Errors say `Failed to decode audio` only for `EncodingError`, else `Could not load the audio`.

### 8.11 Library, storage, mixer
- `.sng` is one song: id = its path, entries carry `sng` so `restoreSongs` reads them through the container; `server.mjs` serves `/songs/<path>.sng/<inner name>` with ranges. Metadata replaces song.ini; inner files are lazy; the XOR mask is undone per file.
- **Search** accepts fields (`artist:`, `album:`, `genre:`, `charter:`, `year:1990-1999`, `len:<4` minutes, `inst:drums`, `no:vocals`, `pack:`, `-field:` to exclude); filters: instrument chips, minimum level, genre, decade. **Thumbnails** (`thumbs.js`): 128 px JPEG under `id@128`, LRU of object URLs (cap 300) + IndexedDB, 3 jobs at a time, dropped if the row scrolled away; a fetch/decode failure is not saved as 'none' (skipped for the session).
- **IndexedDB** (`store.js`): every open has a 4 s timeout and every transaction 8 s (`configureStore({open, tx})` overrides them in tests); every call fails soft; a blocked open waits for that timeout. The connection closes itself on `versionchange`/`close`; the thumbs connection is cached and dropped on any close or failed/hung transaction (reopened lazily), library calls open and close per call. Quota errors and a missing `indexedDB` return false/null/undefined, never throw. `test/store.test.js` uses a fake `globalThis.indexedDB`.
- `scanSongs` (`library.js`) reads `song.ini`/`.sng` through `mapLimit` with `SCAN_CONCURRENCY = 8`; never an unbounded `Promise.all` over library files. An unreadable `song.ini` does not fail the scan (the song stays listed with `ini = {}`); `mapLimit` rethrows the first rejection.
- `showDirectoryPicker` shows a native Chrome dialog the page cannot suppress; "Reopen folder" asks only for read permission, in one click.
- **Mixer stem names:** `relabelStems()` (`songinfo.js`, applied in `selectSong`) shows `rhythm.ogg` as Bass (name and icon) when the song has a bass part, no rhythm part and no stem called bass (Rock Band / Clone Hero store the bass as rhythm.ogg); the stem id stays the file name.

### 8.12 Server and MIDI hardening
- **Server (`server.mjs`).** Binds `127.0.0.1`; `HOST=0.0.0.0` is the explicit LAN opt-in (any Host accepted); on loopback a Host that is not an IP literal, `localhost` or the machine name gets 403 (DNS-rebinding guard). App files resolve after decoding and must be `index.html`/`styles.css` or a script/style/image under `src/` or `vendor/` (`resolveAppFile`; never dotfiles, `server.mjs`, `package*.json`, docs, `test/`, `scripts/`). `/songs` serves only `SONG_EXTS` (audio, images, charts, ini/txt/json/sng), checks `realpath` stays inside the songs folder, and sends `Content-Security-Policy: sandbox`; backslashes, NUL/control chars and (Windows) `:` in paths get 400; every response has `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` and `frame-ancestors 'none'` (`/songs` swaps the CSP for `sandbox`); only GET/HEAD (405); 500s are logged and answered generically; the process survives unhandled rejections. A directory named `*.sng` under `/songs` is served as a plain folder. Tests: `test/server-security.test.js`, `test/server.test.js`, `npm run smoke`.
- **Scan and cache.** `scanLibrary` reads `notes.mid`/`notes.chart` through `readCapped` (64 MB) and skips larger files (`.sng` inner charts above the cap are skipped by index size); the `library.json` cache is checked by `validIndex` (bad shape: rescan). `CACHE_DIR` (or `createServer({ cacheDir })`) relocates `library.json` (temp file + rename); tests and smoke must set it; a `CACHE_DIR` inside `src/` or `vendor/` would make the cache servable.
- **HTTP.** `/songs/*` and static files send a weak `ETag` (size+mtime) and `Last-Modified`; `If-None-Match` (precedence) / `If-Modified-Since` answer 304 (before `Range`). `parseRange()` handles one range: multi/garbage get the full 200, unsatisfiable 416, `If-Range` only with a date, an empty file is a 200 without a stream. Files stream with `stream.pipeline`, headers written on the read stream's `open`, so aborts and mid-file errors destroy the stream and never throw: keep that pattern for any new file route, never `.pipe()`.
- **Compression.** App files with a text extension (`COMPRESSIBLE`: html/js/mjs/css/json/svg, at least 1 KB) and `/api/library` go out in brotli (q9) or gzip (level 9) when `Accept-Encoding` allows (`pickEncoding`, br first, q=0 honoured), with `Vary: Accept-Encoding` (identity answers too) and an ETag per representation (`encodedTag`: `W/"...-br"`), so 304s keep working per coding. Compressed bodies are cached in memory per (path, mtime, size) up to 32 MB (`COMPRESS_CACHE_BYTES`, least recently used out). A `Range` request and everything under `/songs` stay identity. The library JSON is built once per index (`libraryBody`, weak ETag from a SHA-1 of the body, If-None-Match only): 1.39 MB -> 97 KB br / 131 KB gzip on the author's 746 songs. Tests: `test/server-conditional.test.js`.
- **MIDI (`midi.js`, `text.js`).** `parseMidi` treats the file as hostile: VLQs at most 4 bytes, every length checked against its track end, `pos` must advance per event, file size (`MAX_MIDI_BYTES` 64 MB) and event count (8M) capped, a division below `MIN_DIVISION` (24) or an event past `MAX_TICK` (2^31) throws `Invalid MIDI`, as do truncated tracks/events and status bytes 0xF1–0xFE (shown as the load error). Text/lyric/track-name events are UTF-8 when valid, else Latin-1 (like YARG). `phraseWindows` ignores PhaseShift SysEx that is short or has a difficulty byte outside 0–3/0xFF. Out-of-spec velocity bytes with the high bit set are tolerated (a real Rock Band chart has one). `generateBeats` (`chart.js`) stops at `MAX_BEATS` (200,000). Tests: `test/midi-hardening.test.js`.
- **`.chart` and `.sng`.** `parseChart` is capped at `MAX_CHART_BYTES` (64 MB) and `MAX_CHART_EVENTS` (8M lines); lines with a tick above `MAX_TICK` or malformed are ignored, lengths clamped to 0..`MAX_TICK`, tempos outside 1..1e9 millibeats/min and time-signature numerators outside 1..255 ignored, a `Resolution` outside 24..65535 throws (0 or negative falls back to 192). `.sng`: metadata and index sections at most 8 MB (`MAX_SECTION`), counts must fit the section, every file entry must lie inside the container, file data is read only by range. Tests: `test/resource-limits.test.js`.
