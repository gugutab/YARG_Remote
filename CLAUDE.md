## 1. What it is

Web visualizer (HTML + ES modules, **no build**) for songs in the Rock Band / YARG format:
- the user points to a songs folder (`A:\music\Songs\`, or any folder; or `node server.mjs` serves one), the app lists the songs;
- on picking a song, they choose instrument and difficulty, and the app plays the audio stems with a synchronized highway (notes, sustains, solos, star power, rolls, HOPO, open, drums, vocals with lyrics);
- controls: play/pause, seek, sections, per-stem volume, speed (0.2×–2×) without changing pitch, neck speed (spacing only), chart delay (−1 s to +1 s, per window), audio delay from `song.ini`, A-B loop.
- There is no hit/miss detection. It is visualization only.

**Language.** The user writes **Portuguese**; chat replies and discussion with the user are in Portuguese. Everything in the repository is **English**: code, comments, UI text, docs (this file, README) and commit messages.

**UI labels (English):** instruments Guitar, Bass, Rhythm, Keys, Drums, Vocals, Harmony; difficulties Easy, Medium, Hard, Expert (badges E/M/H/X from the `short` field of `DIFFICULTIES` in `chart.js`); drum modes "Drums (4 lanes)", "Drums (5 lanes)", "Drums (Pro)", "Drums (Pro 7 lanes)"; panels Library, Settings, Stem volume, Other song.ini properties.

**Not supported** (pending, in order of likely value):
- `.sng`: not the YARG-encrypted wrapper variant; a `.sng` inside a folder that is also a song is a separate song.
- `.chart`: no GHL tracks, no co-op guitar (`DoubleGuitar`), no versus phrases (`S 0`/`S 1`), no anchors or `[Song] Offset` (ignored, as in YARG), no kick accent/ghost (`N 33`/`N 39`, reserved in YARG), no vocal pitches (a `.chart` has lyrics only, drawn as talkie notes). Forced, tap, open, double kick, cymbal, accent and ghost flags are per difficulty (YARG.Core `ChartReader.ProcessLists.cs`), and so are star power, solo, fill and roll phrases and the tom markers: those notes carry `difficulty` and `buildChart` filters on it (`ChartReader.ReadNotes`, `ConvertSoloEvents`).
- Pro guitar and bass (`PART REAL_GUITAR`, `REAL_BASS`) and Pro keys (`PART REAL_KEYS_*`).
- Open by 5-lane note pattern (only the SysEx and `[ENHANCED_OPENS]` forms are read).
- Fill / BRE only as a faint band: no BRE-specific graphics or scoring, no coda `Coda` phrase.
- Elite Drums (`PART ELITE_DRUMS`) and VENUE/lights.
- Solo only as a background band (star power also recolours its notes, `markStarPowerNotes` in `highway.js`). The comparison with YARG's render and suggestions are in `docs/yarg-render-review.md`. Do not extend solo to per-note without checking YARG first.
- Lyrics: `§`/`=` handled only in a basic way; `#`, `+`, `^`, `*`, `%`, `/`, `$` are hidden but their meaning is applied (§6). The Unity-side vocal UI is not in YARG.Core, so how YARG draws talkies and uses range shifts is inferred from the data.

## 3. Run, test, verify

```bash
npm start              # node server.mjs [songsDir]; env SONGS_DIR, PORT=8080, HOST=127.0.0.1; open http://localhost:8080
npm run start:static   # python -m http.server 8080 --bind 127.0.0.1 (folder picker only, no server features)
npm test               # node --test test/*.test.js (no browser, 355 tests at last run)
npm run smoke          # scripts/smoke.mjs: server on a free port + temp synthetic song; non-zero exit on any failure
node scripts/find-special-notes.mjs <folder> [--only open,accent] [--max 5] [--json]
```

- Dev server: `node server.mjs [folder]` (default `A:\music\Songs`, or `SONGS_DIR`). The app detects it (`startLibrary` in `app.js`) and opens the library with no folder picker. `HOST=0.0.0.0` is the explicit LAN opt-in (§8 Server). The refresh button redoes the scan. Index cache: `.cache/library.json` (git-ignored).
- `smoke.mjs` backs up and restores `.cache/library.json` (the server overwrites it, and it holds one `songsDir` only).
- Unit tests use synthetic MIDIs from `test/smf.js` (an SMF writer for tests only). **Do not commit the user's real songs**: they are copyrighted and stay outside the repository (`.gitignore` blocks audio, `.mid`, `.sng`, `song.ini`).
- The `Read` tool does not read `.mid` (binary). Inspect with the project parser (`src/midi.js`) or a Python script with `struct`.

**Visual verification** (a unit test is not enough for drawing; take a screenshot):
- Playwright from `npm root -g`; system Chromium: `chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })` (Linux sandbox). Do not run `playwright install`. On Windows the Playwright MCP browser also works (`.playwright-mcp/` is git-ignored; screenshots at the repo root too).
- Load a folder with `page.setInputFiles('#folderInput', '<directory path>')`. The input is `webkitdirectory`, so it needs a real directory, not a file list. Or run `node server.mjs <folder>` and just open the page.
- Each test song is a folder with `notes.mid`, `song.ini` and a silent `song.wav` (audio is needed for the song to open; an 8 kHz mono WAV of N seconds works; `scripts/smoke.mjs` has a WAV writer).
- Position with `#seek` (`value` plus `input` and `change` events), or open a deep link (§8 Deep links).
- The canvas has height `min(70vh, 620px)`. Crop the screenshot to the full height or the lyrics (below the canvas) are left out.
- Do not use `pkill -f <pattern>`: the pattern matches the shell itself and kills the session (exit 144). Keep the PID of the server and `kill` it.
- Browsers block sound before a click, so a headless run cannot start playback by itself; headless only checks the clock.

**Perf recipe.** Settings `perf.overlay` (off/compact/detailed, key P or click the chip) shows fps, frame avg/p95/max, draw ms, dropped frames (gap > 1.5× median or > 25 ms), long tasks, canvas size, dpr, panes, JS heap (Chromium), audio output latency and "music clock jitter" (`perf.clock`). Notes-on-screen and audio drift are not measured. To find garbage per frame: Playwright `page.context().newCDPSession(page)`, `HeapProfiler.startSampling` with `includeObjectsCollectedBy*GC`, then sum `selfSize` per function after `stopSampling`. Measure frame time at the display's vsync (e.g. 6.4 ms at 160 Hz). Reference numbers are in §8 Highway rendering.

## 4. Architecture

Flow: folder (or `/api/library`) → `library.js` (songs) → click → `midi.js` / `chartfile.js` / `sng.js` (parse) + `chart.js` (chart) → `highway.js` (drawing, a pure function of `t`) and `player.js` (audio). `app.js` wires up the UI.

## 5. Data model and clock

Chart (`buildChart`):
- `mode`: `'lanes'` (guitar, bass, rhythm, keys, drums) or `'vocals'`.
- lanes: `notes[] = {time, end, length, lane, cymbal, tap, hopo, open, accent, ghost, doubleKick}`, `lanes`, `laneColors`, `drumKind`, `rolls[]`, `solos[]`, `starPower[]`, `fills[]`, `beats[]`, `sections[]`, `duration`. In drums, `lane = -1` is the kick (full-width bar, not a column).
- vocals: `notes[] = {time, end, length, pitch}` (plus `slide`, `talkie`), `harmonies[] = {part, notes}`, `percussion[] = {time, played}`, `lyrics[] = {time, text, end}`, `phrases` (karaoke lines), `rangeShifts`. Harmony: `chart.lyrics` are YARG's merged static lyrics (karaoke without split), `lyrics1` the lead voice's own words, `lyrics2` the other voices' own words (what the lead does not sing at the same moment).

Library index (`server.mjs`): each song `{id, folder, title, artist, album, ini, parts, files:[{name,path}]}`. `parts` = the instruments its chart really has (from `instrumentOptions`; harmony counts as vocals). `song.ini` often has no `diff_*` or -1 for all, so list icons and the instrument filter use `parts` when present and fall back to the ini levels (folder mode has no `parts`). `INDEX_VERSION` is 4 (4 = .sng songs). Bump it when the index gets new fields so `.cache/library.json` is rebuilt (a full scan reads every chart, ~8 s for 746 songs).

Pack (game/DLC): `packOf(song)` in `ini.js` = the top-level folder of the song's path (40 values in the author's library: "Rock Band 2 DLC", "Guitar Hero III"...; the ini `icon` code is partial). Shown as the first header chip, a line in the large card, a filter, a sort key with dividers, a `pack:` search field (and part of free-text search). Songs in the library root have no pack.

Clock: `player.currentTime()` = chart position. The highway receives `t − chartDelay`, so a positive delay makes the notes arrive after the audio. The current section, lyrics and karaoke use the same time as the highway: changing one without the others breaks alignment.

## 6. YARG rules

Source: `yarg.core` at `github.com/YARC-Official/YARG.Core`. Reference clone used: `/home/user/yarc-official/yarg.core` (may not exist in a new session; clone with `GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1 https://github.com/YARC-Official/yarg.core`). Cite the origin (file and function) in code comments for MIDI rules, as is already done.

| Topic | Rule | Where in YARG.Core |
|---|---|---|
| Difficulties | Base 60/72/84/96 (Easy/Medium/Hard/Expert). Offsets 0–4 = lanes; +5 and +6 = forced HOPO and forced strum. | `MidiInstrumentPreparser.cs`, `MidiFiveFretPreparser.cs` |
| Tap | Note 104 marks a window `[start, end)`; notes inside are tap (all difficulties). | `MidReader.ProcessLists.cs` |
| Natural HOPO | Not a chord, has a previous note (another fret or chord) and distance ≤ `resolution/3 + 1`. | `MoonNote.IsNaturalHopo`, `MidReader.cs` |
| Forced | A 101 window forces HOPO; 102 forces strum. Strum wins over HOPO. | `MidReader.cs` (`ProcessEventAsGuitarForcedTypePostDelay`) |
| Open | SysEx `PS\0`, type 0, difficulty (0–3, 0xFF = all), code 1 = open, value 1 start / 0 end, F7. Notes in the window become open. | `PhaseShiftSysEx.cs`, `MidReader.cs` |
| Enhanced opens | Text `[ENHANCED_OPENS]` / `ENHANCED_OPENS` in a 5-fret track: from that tick on, the note one below each difficulty's green (59/71/83/95) is an open note (`n.open`, lane 0). | `SwitchToGuitarEnhancedOpensProcessMap`, `BuildGuitarNoteProcessDict` (`FretToMidiKey[Open] = -1`) in `MidReader.ProcessLists.cs` |
| Sustain | A note has a sustain if it lasts ≥ `resolution/3` ticks. Drums have no sustain. | `SustainCutoffThreshold` in `MidReader.cs` |
| Drums: type | 101 present = 5 lanes; 110–112 present = Pro; otherwise 4 lanes. | `MidiDrumsPreparser.cs` |
| Drums: pads | Offsets 0 kick, 1 red, 2 yellow, 3 blue, 4 orange (5 lanes) or green (4 lanes), 5 green (5 lanes). | `DrumPadToMidiKey` in `MidReader.ProcessLists.cs` |
| Cymbal (Pro) | Yellow, blue and orange/green are **cymbal by default**. Notes 110/111/112 are **tom markers**: the window of each one does an XOR. Cymbal = even number of markers covering the note. The 5-lane mode applies cymbal flags too (the user asked for this explicitly; do not remove it without asking). | `DrumPadDefaultFlags`, `PAD_TO_CYMBAL_LOOKUP` in `MidIOHelper.cs`, `ProcessNoteOnEventAsFlagToggle` (`note.flags ^= flags`) |
| Pro 4-lane mode | Same notes, no cymbals. The option appears as "Drums (4 lanes)". In the selectors (cards and top menu) the drums are a single item, "Drums", with a mode selector (4 lanes / 5 lanes / Pro / Pro 7 lanes); `instrumentGroups()` in `app.js` (vocals and harmony are also a single "Vocals" item with a selector). | `MoonNoteToFourLane` |
| Pro 7 lanes | Mode id `drums-extended`: 7 lanes, tom and cymbal each in their own (`EXTENDED_DRUM_LANES` in `chart.js`); cymbals drawn as triangles. In YARG this is per profile (Split/Merge in `DrumsHighwaySpecs.cs`); the exact order after the split was not confirmed. | `DrumsHighwaySpecs.cs` |
| Accent / ghost | Velocity 127 = accent, 1 = ghost, pads only (not kick). | `MidIOHelper.VELOCITY_ACCENT/GHOST` |
| Double kick | A note one below the difficulty's kick (95 on Expert) becomes its own kick, at its tick, with the flag. | `MidReader.ProcessLists.cs` (`key - 1` with `InstrumentPlus`) |
| Rolls | 125 kick roll, 126 tremolo, 127 trill (time spans). | `MidIOHelper.cs` |
| Fills / BRE | Drums: notes 120–124 are activation phrases (`chart.fills`, kind `fill`); with a `coda`/`midcoda` event those starting inside a coda become `bre`. Guitar-like parts: note 120 is a BRE, valid only entirely inside a coda. Coda ranges: `midcoda`…`midcoda_end` pairs and a last `coda` to the end. | `DRUM_FILL_NOTE_*`, `ReplaceDrumFillDuringCoda`, `GetCodaRanges` (`MidReader.ProcessLists.cs`); `ValidateGuitarPhrase` (`MoonSongLoader.Guitar.cs`) |
| Sections | Text in the `EVENTS` track as `[section Name]` or `prc_name`. Current section = last one started; before the first, the first. The name is the text after the `section`/`prc` prefix with leading `_` and spaces trimmed; `displaySectionName` only tidies it for display (underscores to spaces, each word capitalised: `chorus_1` → Chorus 1, `gtr_solo_a` → Gtr Solo A; no abbreviations expanded). A song with no sections gets ten automatic ones, `0% - 10%` … `90% - 100%`, over the song's last tick (`autoSections` in `chart.js`). | `TextEvents.TryParseSectionEvent`, `PracticeManager.FindSectionAtTime`, `SongChart.AutoGeneration.cs` |
| Time signature / beat grid | Meta 0x58 (numerator, denominator = 2^n) → `midi.timeSignatures`. BEAT track notes 12/13 win; with none, lines every `resolution*4/denominator` ticks, restarting at each signature change, a measure line every `numerator` lines (x/1: only the first), default 4/4. | `SyncTrack.GenerateBeatlines` (`FinishLoading`) in `Chart/Sync/SyncTrack.cs`; `ReadSongBeats` in `MidReader.cs` |
| Tempo | Tempo map summed across all tracks (meta 0x51), integrated `tick → seconds`. | `SyncTrack.cs` |
| Delay | `delay` (ms) if ≠ 0, otherwise `delay_seconds`. File position = chart time + delay. | `SongMetadata.cs`, `SongRunner.cs` |
| Wait countdowns | A chart with nothing to play for 9 s or more (also before the first note) shows a ring with the seconds until its next note, per pane; suppressed in a coda. | `GetWaitCountdowns`, `WaitCountdown.MIN_SECONDS` |
| Lyrics | Lyric events (meta 0x05) in the vocal track; if there are none, text without brackets (e.g. `5395826e`, `5875318f`). | `MidReader.cs`, `LyricSymbols.cs` |
| Lyric symbols | Hidden: `+ # ^ * % / $`. `=` = hyphen. `§` = joined syllables (`‿`). `-` stays. | `LyricSymbols.cs` |
| Vocals | Notes 36–84 (0 range shift, 1 lyric shift; 96 played and 97 not played are percussion). Harmonies: `HARM1`–`HARM3` or `PART HARM1`–`HARM3`. | `MidIOHelper.cs` |
| Vocal phrases | Notes 105/106 are scoring and static lyric phrases (`phraseRanges` in `vocals.js`). Lyrics go to the notes in a phrase by tick; a lyric takes the length of its nearest unclaimed note and lyrics no note claims are dropped (`chart.lyrics[].end`). HARM3 uses HARM2's phrases. | `MoonSongLoader.Vocals.cs` (`GetVocalsPhrases`, `FixLyricLengths`), `MidReader.ProcessLists.cs` (`CopyDownPhrases`) |
| Karaoke lines | `chart.phrases` = static lyric phrases split at lyric-shift notes (note 1; else the end of a syllable marked `/`), at gaps ≥ 0.4 s between syllables (not after a joined one), and by character count (> 50: `ceil(chars/37.5)` chunks, cut at the first word boundary past the target). Charts without phrases fall back to the same time/character rules over the lyrics (`karaoke.js`). | `SplitStaticLyricPhrases`, `SplitPhraseByTime`, `SplitPhraseByCharacterCount`, `StaticLyricConstants.cs` |
| Pitch slide / talkie | A lyric ending in `+` makes its note a continuation of the previous one (`slide`, drawn joined; no syllable of its own); `#`, `^`, `*` make the note unpitched (`talkie`, drawn as a dashed box in the middle of the range, ignored by the range). | `LyricSymbols.cs`, `MoonSongLoader.Vocals.cs` (`GetVocalsPhrases`, `GetVocalNotePitch`) |
| Range shifts | Points: note 0 (length = its duration), `[range_shift]` / `[range_shift 0.5]` text, lyric ending in `%`. Each range covers the pitched notes up to the next point (`chart.rangeShifts`). With more than one range `Highway.vocalRange` uses the one in force at `t` (eased over its length); with one, it scans ahead. | `GetRangeShifts` |
| Harmony lyrics | Static phrases of HARM2 and HARM3 merge by start tick (words within a 16th note: same text keeps one with the earliest start and latest end, a lower-case start wins; otherwise both, in the order that reads best), then merge with HARM1's; `$` hides a lyric. | `MergePhrases`, `MergePhrasePair` |
| Vocal view geometry | A note is 1.5 semitones thick (`leadHalf`, floor 6 px) and the pitch area is at most `max(150, w/6)` px tall (`vocalMaxArea`), anchored above the lyrics. The pitch range itself matches YARG. | `VocalTrack.cs` |

## 8. Gotchas by area

### CSS and layout
- **Containing-block trap:** never put `backdrop-filter` (or `filter`/`transform`) on an element that contains `position: fixed` popovers: it becomes their containing block and they are placed relative to it (this pushed the section list far to the right and made the page scroll sideways). The glass top bar blurs through `.topbar::before` for that reason.
- **Container queries:** `.main { container-type: inline-size; container-name: song }`. The narrow-layout rules of the bar are `@container song (max-width: 700px)` (album art from 440 px), so they also apply when the library is open and the window is 700–900 px wide. Other containers: `.info-grid`, `.card-volume` (`volume`). Many bar rules are on the *main area* width, not the window width.
- `<symbol>` + `<use>`: the document stylesheet's `svg path.fill` rule does not reach the elements inside a symbol, so `#i-play` / `#i-pause` carry an inline `style="fill:currentColor;stroke:none"` (solid everywhere).
- Large screens (`styles.css`, "Round 56"): breakpoints at 1800, 2300, 3000 px widen the library (`--lib-w`) and the bar's content cap; the detail screen (`.info-grid`) is capped at 1400 px; the 2D lanes grow with the stage height (`laneW` in `highway.js`). CSS `zoom` was tried and rejected: it breaks coordinates for popovers, the scrollbar rail and the canvas.
- Library window (list + song details): `#library` is ONE glass window floating over the stage (inside `#stage`, `position:absolute`, `--lib-gap` 12 px margin, `z-index` 12, translucent `--panel` 78%). It is a flex row with two panes: `#libList` (the library column, `.lib-list`, including `#splitter`) and `#info` (the song details; `hidden` and `inert` while closed; ids `#infoWindow`, `#infoWinTitle`, `#infoWinArtist`, `#infoClose`, `#infoPlay`). Border, shadow and blur are one layer, `.library::before`: never put `backdrop-filter`/`filter` on the aside or on `#info`. The window never takes room from the chart: the stage always spans the whole screen, so opening or closing anything resizes nothing. It sits between the top edge and the player bar, bar at the bottom or at the top.
- Open and close: `setLibraryOpen` toggles `.app.lib-closed` (the list pane) and `setInfoOpen` toggles `.app.info-open` (the details pane); `syncWindow()` then sets `.details-only` (details open, list closed: the window shows only the details pane, anchored at `--lib-left`; closing them hides the window; L / `#libTab` bring the list next to it) and `inert` on the aside (when neither pane is shown) and on `#libList` (list closed). The window slides and fades with transform and opacity (0.22 s); hidden means `visibility:hidden`, so the virtual list keeps its size. Controls: L, `#libTab`, `#closeLibrary`, `#welcomeOpen`; details: I, Esc, `#infoClose`, Play. `#settingsTab` (gear edge tab, shown while the list is closed) keeps Settings reachable; `,` also works. Opening Settings closes the list first, then the details.
- Width (`layoutWindow()` in `app.js`; runs on open/close of either pane, resize, splitter drag and a `details.maxWidth` change): it computes `--list-w`, `--info-w` and `--win-w` (list + details + 2 px border) from the content area (`--content-max` 1400 px centred, from `--lib-left`; `CONTENT_MAX` and `LIB_MARGIN` in `app.js` must match `--content-max` and `--lib-gap`). The list keeps its chosen width (`--lib-w`, remembered in `yargremote.libWidth`; min 300 px = `MIN_LIB_W`); the details get `min(details.maxWidth, room - list)`; when both do not fit the list shrinks first (down to 300; `maxLibWidth()` leaves the details `INFO_MIN_W` = 380 px of room while they are open) and then the details go narrower than 380. `#splitter` sits on the list pane's right edge: the window's right edge while the details are closed, the divider between the panes while they are open; double-click resets the width. Closing the details with the list open (`setInfoOpen(false)`) keeps the window's total width: the list takes all of it and stores it as `libWidth`. The width animates (`transition: width`, off while dragging).
- Insets: `.app` gets `--lib-inset` (`--lib-left` + `--win-w` + gap) while the list is open or `.details-only`; `.welcome`, `.end-screen` and `.load-screen` use it as `padding-left` so their content stays in the free area. The canvas does not use it (the left of the leftmost fretboard and the perf overlay sit under the window while it is open).
- Phone (≤ 700 px): the window is a full-height fixed drawer with `#scrim`, over the bar (CSS sizes it; `layoutWindow` removes its variables). It starts open only if the URL does not name a song. While the details are open it is full width showing only the details (`#info`), the edge tabs are hidden, X (`#infoClose`) returns to the list and Play closes the drawer; picking a song no longer closes the drawer there. `#settingsTab` is hidden (settings via `#libTab` then the gear in the library header).
- Panels settings: `panels.libraryStart` (open/closed/last; state in `yargremote.panelState` `{library}`) and `panels.libraryAutoHide` (desktop only: close the list pane when a song is picked, default false; the details stay). `panels.songStart`, `panels.openSongOnSelect`, the `songPanel` shortcut (D), `#songTab`, `#closeSongInfo` and the `song-closed` state were removed; the details close with I, Esc or Play.
- z-order: `.end-screen` 6 < `.load-screen` 11 < `.library` 12 (list and details) < player bar 13 < immersive bar 14 < `.popover` 20 < drawer 30 < edge tabs 40 < `.sel-pop` 50 < settings page 80. The details have no layer of their own.
- Peeking (`setupPeek` in `app.js`, `PEEK` timings): resting the pointer on the tab of a hidden menu for 1 s opens it temporarily and saves nothing; it closes 2 s after the pointer leaves or 3 s after it stops moving over it, unless a popover is open or an input inside has focus. A click opens it for good. No peek on touch screens or phones.

### Highway rendering: layers, fades, visualizers, perf
- Fretboards have no stage-colour base: the road is the faint white tint and lane guides. The board has a neutral black base whose opacity is `highway.trackOpacity` (0–100, default 75; drawn in `renderLanes` and `renderLanes3D`), added last with `destination-over`, so it is not thinned by the fades.
- Edge fades: with a visualizer each lane pane is drawn on its own offscreen layer (`drawPane` / `layerFor`, `this.layered`) and the fades erase it (`destination-out` via `fadeStyle`) instead of painting the stage colour; the notes/guides/halos are erased, the base is re-added. The top fade is a transparency mask over everything including the base, shorter (3D 26% of the height, 2D 12%) with a 12-stop smootherstep ramp; the bottom fade only erases notes/guides and the black base stays (reads as fade to black). The bottom fade is limited by the room under the pads: the pads must not move up (3D keeps 26 px under them, 2D `HIT_Y` stays 0.93). Readability helpers never use the stage colour: vocal/lyric `trackBase`, the karaoke "already played" dimming and the sheet fades use black. Lyric-sheet rows are drawn on their own layer (`rowLayer`) so the fades erase only the words; the rail and jump button are drawn after.
- Seek animation: `visualChartTime` (app.js) eases only the time the highway draws when the song jumps (> 0.75 s between frames: seek bar, wheel, arrows, section, lyric line): ease-out, 0.28 s + 25 ms per second of distance, 0.7 s at most. Clock, sections and audio use the real time. Setting `highway.seekAnimation`.
- Motion blur: while a seek animation moves the drawn time faster than 0.06 s per frame, `Highway.renderBlur` draws the chart at 8 moments across most of that frame's time step (offscreen canvas, running 1/(i+1) alpha average). Setting `highway.motionBlur`.
- Scrub on seek: while the song plays, a long seek (> 0.75 s, animation setting on) goes through `seekTo` → `player.scrubTo(t, ms)`: the worklet (`player-worklet.js`, helpers in `scrub.js`) rushes through the skipped stretch as short Hann grains following the same ease-out path as the fretboards for the same duration (`seekAnimMs`, handed over by `pendingSeekDur`), then plays from the target with a short fade-in. The chart clock is the target at once. Paused seeks, the loop wrap (its fretboards still animate) and the legacy engine cut the audio immediately.
- Background visualizers (`visualizers.js`, `Highway.setVisualizer`, popover `#visualizerPop`, G / Shift+G): one animated background for the whole canvas, drawn in `Highway.draw` right after the background fill, under every pane (motion blur draws it once per frame and reuses it). Every effect is a pure function of song time `t` (beat position from `chart.beats`, note density integral, star power spans, vocal and percussion activity, chart notes as a spectrum) plus the cover palette (32×32 downscale, `extractPalette`), so pausing freezes it and seeks just land; `createDriver` builds per-song data (`buildSongData`, rebuilt when `highway.panes` changes) and draws the effect. Effects: Album art, Aurora, Synthwave, Warp, Beat rings, MIDI equalizer, Embers, Radial spectrum, Spotlights, Tunnel (default `none`). A throwing effect disables itself. `stats` (exported) keeps the running draw cost per effect. No audio analysis (the player graph is untouched). Visualizers do not punch on the beat (`beat.pulse`/`measurePulse` forced to 0 in the driver); tempo-locked motion stays. They are drawn as is (no overlay/visibility slider); the stage colour is passed to effects as `s.stage` ('r, g, b'); those wanting it read `hw.bgRgb`. Pure helpers tested in `test/visualizers.test.js`.

### Audio and player
- `player.js` uses an `AudioWorklet` (`player-worklet.js` + `mixstretch.js`) that mixes all stems and applies the time-stretch (SoundTouch) once, with a single read position; the chart clock interpolates the position history the worklet reports (`clock.js`) at the instant `ctx.currentTime − output latency` (extrapolating with the current speed caused jumps when changing speed; reports arrive ahead of what is heard, and `epoch` discards reports prior to a seek). This fixed the loss of sync between stems and chart of the old engine (one `ScriptProcessor` per stem on the main thread, still present as the fallback `LegacyPlayer`, which adds latency that the highway clock does not compensate). Core test: `test/mixstretch.test.js`.
- Smooth music clock: `WorkletPlayer.currentTime()` runs on the real clock between frames and is pulled towards the audio position (time constant 0.15 s; gaps over 0.1 s snap), because the raw audio clock moves in steps (worklet reports every ~12 ms, `ctx.currentTime` in audio blocks). Measured jitter rms 4.6 ms / max 10 ms before; rms 0.5 ms / max 1.2 ms after; using the animation frame's own timestamp (`player.frameNow`) gives rms 0.3 ms. The perf overlay's "music clock jitter" line checks it.
- **Worklet start watchdog:** `AudioWorklet.addModule` can stay pending forever in Chrome (seen as "Loading audio" stuck at 2% with an empty console, while decodeAudioData and the audio clock still work). `WorkletPlayer.setup()` gives up after `WORKLET_START_MS` (6 s) and `MultiTrackPlayer.load` falls back to `LegacyPlayer` (console warning "AudioWorklet unavailable, using the legacy player"). The cause is unknown; it went away in a fresh browser context.
- **Unload:** `player.unload()` frees the decoded stems (worklet `unload` message / legacy buffers), invalidates in-flight loads (generation bump in both `LegacyPlayer` and `WorkletPlayer`; `WorkletPlayer.load` takes its generation before the setup await) and resets the position to 0; called when another song is picked and at the start of every `load()`, so the peak is one song, not two.
- Stem decode failures: `decodeAll` (`stemdecode.js`) decodes stems one by one and skips the ones that throw (`console.warn` with the id); only if none decodes does `load()` fail (first error's message). Both players only know the decoded stems; `setVolume` of a failed id is a no-op; `player.failedStems = [{ id, label, error }]`. `app.js` marks those `stemStates` as `failed` (row disabled, tooltip "Could not be decoded") and the ready text says "N stems could not be decoded".
- `showDirectoryPicker` shows a native Chrome dialog the page cannot suppress. "Reopen folder" asks only for read permission, in one click.

### Library
- `.sng` is one song: id = its path, entries carry `sng` so `restoreSongs` reads them through the container; `server.mjs` serves the same URLs (`/songs/<path>.sng/<inner name>`), ranges included. Metadata replaces song.ini; inner files are lazy; the XOR mask is undone per file.
- Search accepts fields (`artist:`, `album:`, `genre:`, `charter:`, `year:1990-1999`, `len:<4` in minutes, `inst:drums`, `no:vocals`, `pack:`, `-field:` to exclude); filters: instrument chips (all selected), minimum level, genre, decade. Thumbnails: 128 px JPEG stored under `id@128`, LRU of object URLs (cap 300) + IndexedDB, 3 jobs at a time, dropped if the row scrolled away.
- IndexedDB (`src/store.js`): every open has a 4 s timeout and every transaction 8 s (`configureStore({open, tx})` overrides them in tests), and every call still fails soft; a blocked open waits for that timeout. The connection closes itself on `versionchange`/`close`; the thumbs connection is cached and dropped on any close or failed/hung transaction (reopened lazily), library calls open and close per call. Quota errors and a missing `indexedDB` return false/null/undefined and never throw. `test/store.test.js` uses a fake `globalThis.indexedDB`.

### Server and MIDI hardening
- **Server (`server.mjs`)**: binds `127.0.0.1` by default; `HOST=0.0.0.0` is an explicit opt-in for the LAN, then any Host header is accepted; while on loopback a Host that is not an IP literal, `localhost` or the machine name gets 403 (DNS-rebinding guard). App files are resolved after decoding and must be `index.html`/`styles.css` or a script/style/image under `src/` or `vendor/` (`resolveAppFile`; never dotfiles, `server.mjs`, `package*.json`, docs, `test/`, `scripts/`). `/songs` serves only song-pack extensions (`SONG_EXTS`: audio, images, charts, ini/txt/json/sng), checks `realpath` stays inside the songs folder (symlinks/junctions), and sends `Content-Security-Policy: sandbox`; backslashes, NUL/control chars and (Windows) `:` in paths are refused (400); every response has `X-Content-Type-Options: nosniff`; only GET/HEAD (405 otherwise); 500s are logged and answered generically; the process survives unhandled rejections. Tests: `test/server-security.test.js`, `test/server.test.js`, and `npm run smoke`.
- **MIDI (`midi.js`, `text.js`)**: `parseMidi` treats the file as hostile. VLQs are at most 4 bytes, every length is checked against the end of its track, `pos` must advance on each event, file size (64 MB) and event count (8M) are capped, a division below `MIN_DIVISION` (24) and an event past `MAX_TICK` (2^31) throw `Invalid MIDI`, as do truncated tracks/events/status bytes 0xF1–0xFE throw `Error('Invalid MIDI: ...')` (shown as the load error). Text/lyric/track-name events are UTF-8 when valid, else Latin-1 (like YARG). `phraseWindows` ignores PhaseShift SysEx that is short or has a difficulty byte outside 0–3/0xFF. Out-of-spec velocity bytes with the high bit set are tolerated (a real Rock Band chart has one). `generateBeats` (chart.js) stops at `MAX_BEATS` (200,000). Tests: `test/midi-hardening.test.js`.
- **`.chart` and `.sng`**: `parseChart` is capped at 64 MB (`MAX_CHART_BYTES`) and 8M lines (`MAX_CHART_EVENTS`); lines with a tick above `MAX_TICK` or malformed are ignored, lengths are clamped to 0..`MAX_TICK`, tempos outside 1..1e9 millibeats/min and time-signature numerators outside 1..255 are ignored, a `Resolution` outside 24..65535 throws (0 or negative falls back to 192). `.sng`: metadata and index sections are at most 8 MB (`MAX_SECTION`), counts must fit the section, every file entry must lie inside the container, and file data is read only by range. Tests: `test/resource-limits.test.js`.
- **Server scan and headers**: `scanLibrary` reads `notes.mid`/`notes.chart` through `readCapped` (64 MB) and skips larger files; `.sng` inner charts above the cap are skipped by index size; a directory named `*.sng` under `/songs` is served as a plain folder; the `library.json` cache is checked by `validIndex` (bad shape: rescan); every response carries `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'` (`/songs` replaces the CSP with `sandbox`). `parseRoute` keeps only easy|medium|hard|expert difficulties.
- Conditional requests: `/songs/*` and the static files send a weak `ETag` (size+mtime) and `Last-Modified`; `If-None-Match` (precedence) / `If-Modified-Since` answer 304 (before `Range`). `parseRange()` handles one range only: multi/garbage ranges get the full 200, unsatisfiable 416, `If-Range` is honoured only with a date, an empty file is a 200 without a stream.
- Files are streamed with `stream.pipeline`, headers written on the read stream's `open`, so aborts and mid-file errors destroy the stream and never throw. Keep that pattern for any new file route; never go back to `.pipe()`.
- `CACHE_DIR` (or `createServer({ cacheDir })`) relocates `library.json` (written via temp file + rename). Tests and smoke must set it; a `CACHE_DIR` inside `src/` or `vendor/` would make the cache servable.
- `scanSongs` (src/library.js) reads `song.ini`/`.sng` through `mapLimit` with `SCAN_CONCURRENCY = 8`; never an unbounded `Promise.all` over library files. An unreadable `song.ini` does not fail `scanSongs` (the song stays listed with `ini = {}`); `mapLimit` still rethrows the first rejection.
- Settings read from storage or an import are validated by `buildValidator(SECTIONS)` (schema-driven) passed to `createSettings({ validate })`: a new item type needs a case in `checkItem`, a new custom id an entry in `CUSTOM_CHECKS`, or its stored value silently resets to the default. `importJson` returns `{ imported, skipped }`. Only ids in `defaults` are read (`Object.hasOwn`): never `id in defaults` or untrusted keys on plain objects. `settings.set()` itself is unvalidated (internal callers only).

A `/play` link closes the details without growing (`setInfoOpen(false, { grow: false })`) and counts as a played stage (`markStageLive()`), so its bar shows; closing the details of a never-played song shows the chart but keeps the bar away (`stage-unborn`) until the audio has loaded (or failed to decode). Esc closes the details whatever the load state.
- A pointerdown outside the window closes the details only in details-only mode; with the list pane open next to them the window stays (the chart behind it can be used).
- A `/play` link also loads on the plain background: its details close with `release: false`, so the stage stays held (no bar, no tracks) until the link's audio has loaded (`ensureAudio` starts it, load error releases it).
- The load screen (`.load-screen`) has no background of its own (transparent): what shows is the stage; with the held stage that is the plain stage colour.
- While the held song's audio loads the frame loop's `draw` only repaints the background canvas (`highway.drawBackground`, driven by `loadingBackdrop`), so the chosen visualizer animates behind the transparent load screen; the fretboards and the bar stay away.
- End window: "View my library" (`#endSearch`, `closeSong()`) closes the song: audio unloaded, `current`/`chart` and the panes cleared, the player bar gone again (`stage-unborn`, `stageEverLive = false`), the welcome state back, the URL `#/`, and the library window opens with its search focused. The instrument tables are flex items (`flex: 1 1 230px`, `max-width: 380px`, left aligned, wrapping): they grow from 230 to 380 px to fill the row and never spread apart with gaps.
- Rests: `Highway.restFade(pane, t, appearIn)` (0..1, eased) follows the wait countdowns of the pane (`waitCountdowns`, independent of the countdown setting): in a long rest it goes to 0 and it is back to 1 `REST_BACK_SEC` (1 s) before the next note appears at the far edge (`appearIn` = the seconds a note is visible ahead of the hit line: the window length). The vocal notes view hides its lyric track with it; the fretboards (2D and 3D) multiply their dark base opacity by `restBoard()` = `REST_BOARD_MIN` (0.2) .. 1, so the board turns more transparent during a long rest.
- Sizes: the vocal notes lyric font is 24-36 px (was 18-30); the pane tags (instrument icon + chevron) are 34 px high with 22 px icons. `details.maxWidth` (default 1400, 600-3840 step 40) caps the details pane; the content area (`--content-max`, also set by `layoutWindow()` on `:root`) is `max(1400, list + details max + margins)` up to 3840, so on a 4K screen the library window can be as wide as the setting says.
- Bar tools on wide screens (`@container song (min-width: 800px)`): the volume button shows the master level (`#mixerVal`, `Muted` when muted, updated in `applyStem`) and the speed button the speed (`#speedVal`, two decimals without trailing zeros: 1×, 0.75×, updated in `setSetting`); `.tools` gap 12 px; the two buttons are as wide as icon + text need (6 px padding on every tools button, 5 px between icon and text, 12 px between buttons; the compact bar uses 5 px padding and 8 px gaps with `width: auto` against its 30 px default: the hover highlight hugs each button and the visible gaps are even) and follow the text. Both spans are hidden elsewhere.
- Mouse wheel: over any `input[type=range]` (except the seek bar, which keeps its own 5 s/notch wheel) one notch moves one step (2% of the range for fine-grained sliders), touchpad fractions accumulate, and `input` + `change` events fire; over the bar's volume button it moves the master volume by 5% per notch and un-mutes.
- A `/play` link at startup opens with the library window closed (whatever `panels.libraryStart` says); a details link (`#/song/<id>`) keeps the usual start state.
- In a long rest the whole fretboard (dark base, light tint, bands, beat lines, lane guides and rails) fades by the same `restBoard()` factor (`globalAlpha` around the board part of `renderLanes`/`renderLanes3D`), not only the dark base: fading the base alone made the board look whiter.
- The highlight of the divider lines between the instrument windows (`Highway.drawDivider`, hover/drag) uses the theme's `--accent` (`themeAccent()`, re-read every 500 ms) instead of a fixed blue.
- Mixer stem names: `relabelStems()` (songinfo.js, applied in `selectSong`) relabels `rhythm.ogg` as Bass (name and icon) when the song has a bass part, no rhythm part and no stem called bass (Rock Band / Clone Hero store the bass as rhythm.ogg); the stem id stays the file name.
- 3D road width (`renderLanes3D`): `0.94 * w` in a pane taller than wide, then `min(1.05 * h, 0.94 * h + 0.16 * (w - h))`: continuous at w = h (it used to drop from 0.94w to 0.62w there) and capped at 1.05 h, so widening a window only grows the side gaps once the cap is reached.
